# 原版缺陷防引入清单

确认日期：2026-10-08。用户决定：原项目的问题暂不修复，ReelNest 重构时不要重复引入。

以下风险已通过原 MediaLib 当前源码静态核查，尚未在 macOS 做故障复现。源码路径相对原仓库，行号为核查时位置。这里只记录迁移约束，不修改原仓库，不提前创建未迁移模块，也不宣称当前 Flutter 已存在或已修复这些问题。原功能和 UI 保持一致，不要求复制错误行为。

## D1：远程响应在接收期间限制大小

- 原位置：`Sources/MediaLibServer/ServerRemoteAssetFetcher.swift:365`，`performResponse` 用完整响应回调取得 Data，之后才检查大小。涉及封面、字幕/元数据和单字节长度探测；视频正文另有分块 Range 校验，不把两条通道混为一谈。
- 迁移要求：读取响应头后尽早拒绝不符合要求的状态、Range 或已知超限长度；接收过程中累计实际数据大小，超过上限立即取消。不能仅依赖 Content-Length、超时或并发限制；需保留原有重定向、origin 和凭据边界。
- 待回归：上游忽略 Range 返回 200 整片；无 Content-Length、分块传输及虚假长度的超大正文；上限边界；取消和超限后资源释放。断言在完整下载前停止，不能只验证最后返回错误。使用受控数据流，不通过耗尽内存来测试。
- 触发阶段：对应客户端远程资源读取或可选 ReelNest Server 资源代理迁移时，按各自适用范围验证。

## D2：清理不得删除正在提交的缓存

- 原位置：`Sources/MediaLib/App/AppState.swift:7478` 先移入正式缓存目录，再等待字幕同步，最后登记清单；`Sources/MediaLib/App/VideoOfflineCacheStore.swift:528` 清理未登记文件，未覆盖这段提交窗口。
- 迁移要求：使用受保护的暂存文件和明确提交过程。缓存清理、最终文件发布与清单更新需要协调；保护信息必须覆盖文件出现到提交完成/回滚之间的整个窗口。单独锁住某次清单写入或只提前登记都不足以解决完整问题。
- 待回归：在文件落盘、字幕等待、清单提交各处设置可控暂停点，并发触发手工清理或另一下载任务的容量维护；成功缓存仍可读取、清单和文件一致。失败/取消只回收本次未提交资源；应用中断后的暂存资源可识别并清理。
- 触发阶段：离线缓存模块迁移，与 D3 一起设计和验证。

## D3：重下载失败保留旧缓存

- 原位置：`Sources/MediaLib/App/AppState.swift:7450` 在发起新下载前调用 `removeExistingVideoCacheBeforeRedownload`，删除旧视频、字幕和清单；后续失败无回退。影响缓存副本，不是原媒体文件。
- 迁移要求：旧缓存保持可用，新下载使用独立暂存位置，下载和必要校验成功后再提交替换；清单提交失败可以回退。新旧缓存替换及旧字幕回收与 D2 的清理规则统一协调。
- 待回归：网络失败、HTTP 错误、取消、文件校验失败、磁盘或清单写入失败时，旧视频/字幕/记录保持可用；成功后新缓存生效，再清理旧资源。覆盖相同及不同质量目标路径。
- 触发阶段：离线缓存模块迁移。

## D4：持续消费子进程输出，限制终止等待

- 原位置：`Sources/MediaLibCore/Services/MusicTagEditingService.swift:426` 等待退出后才读取 stderr，stdout 未读取；`ThumbnailGenerator.swift:181` 和 `VideoFramePreviewGenerator.swift:395` 也创建未消费的输出管道。`Sources/MediaLib/Views/PlayerView.swift:8073` 的 FFmpeg 宽高比探测存在同类模式。
- 迁移要求：需要诊断时并发持续读取 stdout/stderr，诊断存储限制大小，达到保留上限后仍继续消费或丢弃输出；无需输出时重定向到空设备。超时/取消后的终止等待同样有上限，按平台实现必要的强制结束与资源回收，避免无界等待。
- 待回归：测试子进程同时产生超过管道容量的 stdout/stderr；持续产生错误输出；正常退出、启动失败、超时与取消；不响应正常终止请求时仍在约定时间内结束调用。优先使用可控子进程，不能只用模拟成功结果替代真实管道验证。
- 触发阶段：音乐标签、缩略图、视频预览、媒体探测或其他外部进程模块迁移。
