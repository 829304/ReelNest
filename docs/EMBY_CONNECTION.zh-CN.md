## 原版依据

只读参考原仓库 `Sources/MediaLib/App/EmbyService.swift`、`AppState.connectEmbyServer` / 库选择更新 / 重新认证，以及 `Views/SourcesView.swift` 的来源、连接、策略和同步库设置。

- 登录为 `POST Users/AuthenticateByName`，JSON `Username`、`Pw`；用户名去首尾空白，密码保持原值。
- 获取库为 `GET Users/{userID}/Views`；检查会话为 `GET Users/{userID}`。保留反向代理基础路径、HTTP/HTTPS 与不填协议时默认 HTTP 的规则。
- `X-Emby-Authorization` 遵循 MediaBrowser 身份格式，客户端品牌改为 ReelNest，设备 ID 持久化；用户请求同时传递原协议的 `api_key`。

- 远程来源默认不自动扫描、不启用本地海报/网络刮削/截图回退，文件大小阈值为零；元数据/健康参与默认开启，观看痕迹模式默认双向。当前只保存这些策略，实际远程任务和观看同步分别在 E2/E3 接入。

## 可用入口与状态

“媒体源 → 添加媒体源…”先选择本地或 Emby；Emby 填写连接信息、确认策略后登录。成功登录并验证库响应后保存来源，默认全库。来源“设置”可读取库列表、切换全部或指定库并保存，也可调整参与策略；“重新认证”更新原账号凭据，“移除”同时清理对应安全凭据与来源配置。

加载进度只在请求期间显示；合法空库、请求失败与未同步媒体内容分别显示。选库失败可以重试；自定义范围为空不可保存，取消不会提交草稿。当前远程来源没有同步/浏览入口，避免误走文件目录扫描。

会话恢复使用已保存令牌验证；401 最多重新登录一次并重试原请求。403/451 或白名单/第三方客户端限制提示不会触发认证循环。缺失安全凭据时可重新认证；切换到不同用户 ID 要添加另一个来源，避免混用已有索引和观看记录。

## 实现与存储

- `apps/client/lib/api/emby/emby_client.dart`：协议、地址规范化、DTO 与错误，不依赖 Widget 或数据库。
- `features/sources/data/emby_connection_repository.dart`：来源独立会话、串行操作、保存/删除回滚、库范围与重新认证。
- `features/sources/application/emby_providers.dart`：客户端生命周期、安全存储装配；可达性调用连接服务，不要求文件适配器。
- `features/sources/presentation/emby_sheets.dart`：来源类型、连接/策略、库选择弹窗；由媒体源页面接入。

来源 ID 独立生成，普通来源路径保存 `emby://host/sourceId`。密码、令牌及完整会话只在系统安全存储，键为 `io.github.user829304.reelnest.emby.source.<sourceId>`，不进入普通 SQL 配置或日志。同服务器不同账号也使用不同键。

非敏感服务器地址、用户名、用户 ID，以及稳定设备 ID 使用既有 SQLite 键值表 `player_preferences`；没有新增数据库升级分支、开发历史兼容或自动清库。这里沿用现有存储结构，连接逻辑与播放器设置仓储没有依赖。

登录/库响应失败不保存来源。新凭据先写安全存储，来源与非敏感配置在 SQL 事务中提交；提交失败清理临时凭据。移除时凭据删除失败保留来源，SQL 删除失败恢复旧凭据。请求超时有上限，成功响应按流限制为 4 MiB，错误正文最多读取 8 KiB，避免先读完整响应再检查大小。

跨站或 HTTP→HTTPS 跨 origin 跳转不会转发凭据，提示填写最终地址；同 origin 重定向有次数上限。这一连接限制需要在真实代理环境核对，不声称与原网络栈重定向行为完全一致。
