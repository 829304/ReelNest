## 检测与显示流程

1. 仪表盘或“重新检测”读取当前索引，异步检查本地文件与根目录，计算视频元数据和重复候选；不重新扫描或完整同步 Emby。
2. 仪表盘显示健康评分、来源可用、资料完整、后台任务四卡，以及本地挂载、核心资料缺口、失效路径、重复组和详情资料缺口。
3. 忽略单项或重复组持久化到现有忽略表，立即重新计分；设置中的“恢复显示”恢复全部忽略项。忽略不会补全资料、修复文件或重复探测目录。
4. 首页被动读取已完成结果，显示总评分与来源/资料比例；首次未检测仍显示待检测，不为首页评分阻塞首屏或探测 NAS。
5. 来源配置、账号、选库或索引事件变化后旧结果失效。旧异步任务即使稍后返回也不能发布到新数据版本。

空数据库显示未添加媒体源，不显示虚假的满分或无限检测。只有延期/移除范围的来源时显示视频检测范围为空。检测失败保留错误状态，不伪装为空库。Emby 尚未完整同步时明确结果只覆盖“已载入内容”，不宣称检查过整台服务器。

### Emby 选库扩大后的完整性（2026-10-12 修复）

此前 `last_scan` 只记录成功同步时间，修改选库不会使它失效：同步过 A、后来增加 B，但新同步失败/取消时，会把旧 A 索引误认作 A+B 的完整索引。本次先用回归复现 `partialIndex` 错误为 `false`，再在仓储的设置保存事务内修复。

- 指定库集合加入新库，或由指定库切换为“全部”，立即清空完整同步标记；索引、播放进度与收藏继续保留。
- 同步网络失败、取消或数据库事务失败后仍保持部分索引。前台分页只能追加缓存，不能恢复完整标记；只有成功提交完整快照后恢复。
- 从全部改为指定子集、缩小范围、只改变顺序或修改无关设置，不撤销原完整标记。集合比较不依赖选库列表顺序。
- 保护放在 `SourceRepository.updateSettings`，同时覆盖连接设置和其他设置调用方；不只修改健康页面或内存状态。没有 schema 升级、历史兼容分支或自动清库。
- 对修复前已经形成的“扩大范围但保留旧时间”状态，现有数据库没有保存当时成功同步的库集合，无法可靠追溯；需重新成功同步一次恢复确切完整性。本次不猜测媒体数量或自动删除开发数据。

## 评分公式

沿用原版两套公式，首页与仪表盘数值本来就可能不同。以下计数均经过当前视频范围、隐私、参与策略和忽略项过滤。

首页：

```text
来源 = clamp(100 - min(离线来源, max(来源总数, 1)) × 22 - 不参与来源 × 4, 35, 100)
资料问题 = 核心资料缺口条目 + 详情资料缺口条目 + 失效网址条目
比例处罚 = round(资料问题 / max(公开顶层媒体数, 1) × 100)
最低处罚 = min(资料问题, 12) × 3
资料 = clamp(100 - min(55, max(比例处罚, 最低处罚)), 45, 100)
总分 = clamp(round(来源 × 0.55 + 资料 × 0.45)
             - min(失效路径条目 + 重复组数, 8) × 2, 42, 100)
```

顶层分母包含影片、系列、其他视频，不把每集再次作为独立顶层计数。核心和详情分别计数；同一影片有两类缺口时会计两次，这是原公式。

仪表盘：

```text
健康问题 = 离线来源 + 失效路径条目 + 失效网址条目 + 重复组数
           + 核心资料缺口条目 + 详情资料缺口条目
健康评分 = 100 - min(健康问题 × 7, 82)
资料完整 = 100 - min((核心缺口条目 + 详情缺口条目) × 6, 80)
```

来源可用沿原版以“来源数减已检测到的离线来源”计算。它不是对每台远程服务器做 HTTP 连通认证的证明；本批不为评分额外登录服务器。来源未知状态在首页来源卡仍独立显示待检测。

## 检查范围与数据边界

| 检查 | 当前行为与边界 |
|---|---|
| 本地文件/挂载 | 保留原根目录与挂载身份保护；离线条目可提示但不能直接当安全清理候选 |
| Emby 路径 | 非系列视频缺少可准备播放地址的远程身份时提示；普通系列容器及省略 `MediaSources` 的浏览结果不误报；不作为本地清理候选 |
| 核心资料 | 本地和 Emby 顶层影视的封面、年份、简介；其他视频不要求影视资料；不逐条请求 Emby 详情 |
| 重复组 | 与原投影一致，仅本地公开顶层候选；标题转小写、去非字母数字字符，结合原类型与年份；未知年份独立分组；跨来源媒体身份互不混淆；查看/忽略，不自动合并删除 |
| 详情资料 | 本地影视的外部 ID、人物、艺术照、推荐记录缺口；当前本地索引仅有核心/NFO 字段及海报引用，四类详情记录尚未迁移，因此如实计为缺口；本批没有实现 TMDB 抓取或一键补全 |
| Emby 详情 | 仍由已有 Emby 详情链路读取；不强制为服务器条目生成本地 TMDB 资料，不把本地详情存储缺口套到 Emby |
| 网址健康 | 公式/结果模型保留原分类；当前没有独立网址来源连接器，生产检测没有此类候选。本批未实现 HTTP HEAD/Range 探测，不把 Emby 视频流当网址来源扫描 |
| 音乐/照片/保险库 | 音乐待独立模块；照片按用户要求移出范围；保险库当前未解锁实现，全部排除。此类根目录仍用于保护重叠路径，但不会被评分顺带探测 |

Emby 只检查当前账号、已选媒体库和当前载入索引；私有/照片/音乐父项及后代排除。嵌套目录按路径边界判定，不能用简单字符串前缀泄漏相邻目录。

本批“评分接通”指当前视频范围的上述计算与结果链路，不代表原版完整健康模块、网址连接器、音乐或元数据修复功能全部完成。网址来源、完整详情持久化/补全、重复合并、公共任务中心与通知继续在对应原功能迁移范围内；没有添加新产品功能。

## 实现与性能

- `features/health/domain/health_score.dart`：纯公式，与 UI 无关。
- `video_health_evaluator.dart`：范围过滤、核心/详情和重复投影；复用 `LocalHealthEvaluator` 文件与挂载安全规则。
- 快照派生缺口列表和重复行一次生成、冻结；页面惰性构建，组内行有高度上限，不逐帧遍历全库。
- 大批量纯数据循环定期让出事件循环并检查取消；远程条目不触发逐项文件或网络 I/O。此措施不等于已经证明真实大库滚动帧率。
- 检测不改变 schema；忽略继续使用现有 `ignored_health_issues` 的类别/来源/本地 ID。重复组键包含排序后的完整复合身份，成员改变后重新提示。
- 清理保留完整原始来源配置用于事务前复核，即使健康评分隐藏音乐/照片来源也不能绕过配置变化保护。不删除本机数据库或媒体文件。

仪表盘概览对照原四卡横向布局：间距 12、内边距 14、圆环 48/描边 6、图文间距 13；按原语义区分正常、警告和失败色。浅深色最小窗口组件图在 `apps/client/build/health-score/`。完整材质、图标、悬停/数值动效及三端原生视觉仍需整体对照，不能以本批截图声称一比一完成。
