# 首页实施计划

计划日期：2026-10-11。目标是在 ReelNest 中迁移原 MediaLib 首页的视频功能、布局和交互；第一阶段 Windows/macOS/Linux。不重新设计首页，不把首页变成另一套媒体源管理页。

## 基线与当前状态

2026-10-12 已实现 H1 首批视频首页：跨来源统计、继续观看、最近播放、想看、收藏、最近添加剧集、详情与播放、滚动分页。实现与验证见 [H1 记录](HOME_H1.zh-CN.md)。同日接入 H2 首批每日推荐轮播、剧集推荐、高分精选、最近剧集看板与题材/离线投影，见 [推荐实现记录](HOME_H2_RECOMMENDATIONS.zh-CN.md)。搜索、运行状态与编排按 H2/H3 继续迁移；未宣称完整首页还原或三端原生验收完成。

本轮只读参考原仓库 HEAD `d94fa15a8139e307c76c36bb07fb9ebe1fa10753` 的本地源码；实施每批时继续核对具体调用和测试：

| 原文件/入口 | 对应迁移范围 |
|---|---|
| `Views/HomeView.swift` | 模块顺序、内容可见性、推荐、问候、搜索入口、查看更多、详情返回和编排 |
| `Views/HomeVividComponents.swift` | 首页页头、推荐轮播、统计、卡片条带、运行状态及布局参数 |
| `App/AppState.swift` 的 `rebuildDerivedItemCaches` | 顶层媒体、单集、来源/隐私/相册边界、播放历史、首页统计与刷新 |
| `MediaLibCore/Models/HomeVideoProjectionPolicy.swift` 及测试 | 下一集、观看阈值与投影规则 |
| `MediaLibCore/Models/MediaPlaybackRecencyPolicy.swift` 及测试 | 真实播放痕迹、最近播放的范围与排序 |
| `MediaLibCore/Models/HomeModuleLayoutPolicy.swift` | 模块顺序归一化、拖动、隐藏、重新添加与恢复默认 |
| `Views/GlobalSearchView.swift` 及其依赖 | 首页提交搜索后的公共搜索结果，不把单库搜索当作全局搜索 |

原版当前 `usesLegacyHomeChrome = false`：总览为默认显示，旧顶部分类标签栏隐藏；页头仍有问候和搜索，首页扫描按钮隐藏。保持这些当前行为，不恢复旧导航。Vivid 参数包括横向留白 36、纵向 28、模块间距 22、标题 18、海报 158×236；主题、组件尺寸、轮播、横向滚动与返回行为逐项对照，不使用默认 Material 卡片代替迁移。

## 数据与职责

首页消费客户端直接管理的本地/移动盘/已挂载 NAS 和 Emby 数据，不调用旧 MediaLib 服务端。未来连接器通过同一首页数据边界接入，本批不实现 Jellyfin/Plex。

- 使用 `(sourceId, localId)` 作为媒体身份；同名作品、相同远端 ID 和多账号不擅自合并。顶层系列进入推荐和统计，单集参与续播与下一集计算，不能把整部剧的全部集数混入推荐墙。
- 来源资格、选库范围、移出库、相册和保险库过滤先于聚合。保险库内容不得进入公开首页、统计、推荐、缓存快照或搜索；相册录像不能误进入影视最近播放。音乐按已确认的独立阶段保留，不在本批混入视频模块。
- 对照原版读取媒体索引、观看记录、本机想看/评级、远端收藏和有效离线清单，保持现有本地/远端观看同步模式。既有 Emby 仓储限定 Emby 来源，不能直接改名后拿来读取本地来源；提取必要的共享映射，新增独立首页查询。
- 继续观看沿原 AppState 的 `0 < playProgress < 0.95` 规则，按最近播放时间排序；不能擅自改为全局已看阈值。下一集沿原投影按季集顺序、最后已完成单集及已看阈值计算，不简单把集号加一。最近播放要求真实痕迹，不能把所有新入库内容当作已播放。
- 首先显示本机已有数据。首次连接但未建全量索引时，复用已实现的 Emby 目录/前台分页按需取得有限候选；不自动等待全库单集同步。缺少完整数据时区分“正在补充”与“库为空”，不把部分数量冒充全库准确统计。
- 各来源独立加载；一个离线或失效来源不能阻塞其他来源，保留有效缓存并显示具体异常。完整首页聚合不依赖每张海报、每个演员详情或所有网络请求成功。
- 来源/选库/扫描、播放窗口通知、收藏/想看/评级、缓存及观看阈值变化触发对应投影刷新；推荐增加日期版本，跨天和恢复前台时更新。旧异步任务不能覆盖新版本结果。主页离开时停止不需要的工作，应用退出时先结束读取/任务再关闭数据库。

建议文件职责（按实施需要建立，不预建空包）：

```text
apps/client/lib/features/home/
  domain/home_snapshot.dart         # 首页数据、模块状态及来源身份
  domain/home_video_policy.dart     # 统计、续播、下一集、历史等纯规则
  domain/home_recommendation.dart   # 原版推荐规则
  domain/home_module_layout.dart    # 编排纯规则
  data/home_repository.dart         # 批量查询、快照和已有来源能力协调
  application/home_providers.dart  # 版本、刷新与异步状态
  presentation/home_page.dart      # 首页装配
  presentation/widgets/            # 原版页头、统计、条带、轮播及编辑控件
```

复用既有详情、播放启动器和图片管线，首页不另做播放器或拼接鉴权 URL。偏好复用现有 SQLite 键值存储；没有开发版本升级链、自动清库或新账号系统。跨来源“查看更多”和详情返回可增加首页内部路由，但保留来源身份与首页返回上下文，不改写媒体源分支的导航含义。

## H1：视频首页基础闭环

**第一批交付一个有真实内容、可进入详情和续播的首页。**

1. 建立首页快照与来源资格过滤，接通本地和 Emby 数据、播放记录及版本刷新。
   现有想看/评级仓储和收藏入口主要围绕 Emby；先核对本地来源是否具备同等状态读写，缺少的最小公共持久化与操作在 H1 补齐，不把“可读取 Emby 收藏”当成本地收藏已经完成。相同动作保持本地保存和远端写回边界。
2. 按原版结构迁移媒体总览、继续观看、最近播放、想看、收藏和最近添加模块；下一集投影接通续播行为，不擅自增加原总览没有的独立模块。
3. 统计影片、系列、剧集、未观看；明确顶层/单集范围。原版“最近添加”模块实际消费剧集候选，不能自行改成所有影片。实施核对发现原 `recentSeriesItems` 的非推荐板回退消费按 `updatedAt` 排序的 `homeVideoItems`，H1 保留这一真实规则；此前计划中“不能用最近更新替代首次入库时间”的断言不适用于该原入口。每日推荐板排序在 H2 单独迁移。
4. 卡片进入既有详情；播放按钮定位正确文件/单集，沿已有队列和进度规则续播。查看更多提供对应完整范围，返回恢复模块和滚动位置。
5. 区分无来源、来源空库、首次加载、后台补充、局部失败和数据库错误；无来源显示原空库引导，不启动无意义扫描。空模块按原可见性规则处理，不占满页面显示重复空提示。

H1 完成条件：只添加 Emby 也有有效首页内容；本地与 Emby 同时可用；关闭播放器后续播卡片/历史刷新，清除记录不被旧通知恢复；删除来源无残留卡片；首页没有展示未接通的搜索/编排操作。H1 是阶段交付，不称完整首页还原；原页头搜索在 H2 接通并完成原交互。

## H2：推荐、搜索与运行状态

1. 迁移每日推荐轮播、剧集推荐、高分精选、相应主题和离线可看投影。逐项保留日期种子、观看/收藏/评级/题材信号、去重、多样性及原取量；不引入新的推荐算法、云端 AI 或必需 TMDB 请求。
2. 轮播先用已有图片，后台按需补 Emby 背景图；图片失败有原版回退，不能阻塞文字、详情和播放。轮播暂停、指针操作和减少动态效果沿原交互。
3. 接通页头问候和搜索：提交进入跨来源视频搜索，清除后回总览；范围和结果行为对照 `GlobalSearchView`，不声称本批完成延后的音乐、照片或公共人物搜索能力。
4. 运行状态模块复用已有健康和任务数据，可进入媒体源、仪表盘和任务中心；读取状态不触发无条件重新扫描或健康检测，不伪造未迁移的后台任务。

H2 完成条件：推荐同一数据/日期可复现，数据和日期改变正确失效；模块之间的原版排除规则生效；离线卡片确有有效缓存；搜索不泄漏保险库、未选库或其他账号内容；首屏不因背景图或某个离线来源整页等待。

### 跨来源视频搜索（2026-10-12，已实现）

本批已接通 H2 搜索闭环，实施与验证边界见[首页搜索记录](HOME_SEARCH.zh-CN.md)；运行状态作为随后一批，H3 编排在两者完成后推进。

1. **页头与返回**：对照 `HomeVividSearchControl` 和 `HomeView`，接入原搜索控件、180 毫秒输入延迟提交及回车立即提交；清空恢复总览。进入结果详情再返回时保留查询和浏览位置，避免切换子树丢失已加载状态。
2. **原匹配规则与展示**：复用现有拼音匹配基础，迁移 `GlobalSearchView` 与 `AppState.mediaSearchFields` 的视频字段：标题/原名、年份、简介、题材、已有演职人员/角色/制作方等资料，以及系列的子集标题和季集信息。单集命中归入系列，不另铺全部单集；按电影、电视剧、动漫、纪录片、综艺、其他分组，组内沿原标题排序和结果行布局。
3. **跨来源与范围**：统一搜索本地/移动盘/已挂载 NAS 及 Emby 的现有索引和已缓存资料；保持来源/账号身份、Emby 选库与移出库过滤，排除保险库、相册和本批延期的音乐。首次尚未完整同步时明确搜索仅覆盖已载入内容；不为每次输入发起全库扫描或逐条详情请求。
4. **异步与性能**：后台处理大库匹配，按来源增量显示可用结果；区分正在搜索、无结果及局部失败。快速改词、清空、来源删除或选库变化后，旧任务不得回写新查询；惰性构建结果，不逐卡遍历全库。
5. **验收**：覆盖中文/英文/拼音/首字母、资料与单集命中、跨来源同 ID、选库/隐私隔离、慢来源、过期返回及详情往返状态。完成相关回归、静态分析、Windows Release 构建与启动检查，再单独进行真实 Emby 只读搜索验证；不把组件测试当作三端原生验收。

本批不接入音乐/照片搜索、公共人物搜索、TMDB 搜索或新服务器连接器。原完整全局搜索中的这些能力仍保留在对应模块的后续范围内。

## H3：首页编排与桌面验收

1. 迁移“编辑首页”：拖动排序、隐藏、添加恢复、恢复默认和完成，偏好重启保留；恢复模块沿原规则追加到当前末尾。
2. 编排只改变模块顺序/可见性，不重算媒体推荐、重新请求全库或重置已有横向滚动。保存失败保留当前编辑状态并允许重试。
3. 完成首页往返详情、轮播/条带横向滚动、查看更多、键盘/焦点与窗口缩放的对照。每批都对照原参数，H3 集中检查剩余偏差，不以最后验收为由先换成另一套 UI。
4. Windows 使用正式 Release 验证已保存的真实 Emby，包括播放/切集/关窗后的首页刷新；macOS/Linux 在相应系统单独构建和验证，不能用 Flutter 平台变体测试替代原生结果。

## 性能与验证

- 首页模块读取有上限的候选和批量统计；单集排序/下一集只读取所需投影。禁止每张卡片遍历全库、逐条统计来源或全库逐项获取详情。需要全量评分时在后台处理并按数据版本缓存。
- 页面惰性构建，复用现有按显示尺寸解码和有界图片队列；预加载只服务当前及附近内容，不把首页图片全部设为最高优先级。滚动、悬停和拖动不得触发全库重算。
- 按原测试迁移阈值、季集/跨季、播放痕迹、排序和模块布局规则；增加同 ID 跨来源、局部失败、选库变化、删除来源、隐私/相册隔离、过期响应与跨窗口刷新回归。
- 大库沿用约九万条模拟/只读索引负载，记录首屏、筛选/推荐处理和滚动表现；不承诺脱离实际设备与网络条件的固定毫秒指标。
- 每批跑相关测试、静态分析、以 `lib/main.dart` 构建 Windows Release 并做启动检查；功能闭环批次再执行适当全量回归。真实服务器读取验证不替用户批量修改状态、下载全库或删除本机数据。

## 保留的依赖边界

音乐推荐/继续听随独立音乐模块迁移；照片墙随相册能力迁移；发布到首页的手动集合随公共集合模块迁移。原首页完整范围中保留这些项，不能因本批未实现而永久删掉或宣称完整首页完成。TMDB 的全球推荐/补充资料、云备份、Jellyfin/Plex 接入不作为本批视频首页前置条件。

实施顺序固定为 H1 → H2 → H3。发现新的原版依赖记录到对应模块；除阻断本批闭环的缺陷外，不把整个公共媒体库重构追加为 H1 前置。
