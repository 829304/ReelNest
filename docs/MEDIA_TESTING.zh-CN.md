# 无现成媒体库与 NAS 的测试方案

日期：2026-10-08。遵循 [项目边界](PROJECT_SCOPE.zh-CN.md)，本方案补充测试条件，不增加或改变产品功能。

## NAS 如何提供媒体目录

NAS 是存储设备，访问方式取决于它开放的服务。文件共享与 Emby/Jellyfin/Plex 媒体服务是两条不同的接入链路：

```text
NAS 文件共享 → 操作系统连接共享 → 可访问的文件路径 → ReelNest 扫描、索引和读取媒体
媒体服务器 → 对应连接器认证、选库与查询 → 媒体详情和播放资源
```

SMB 是本轮网络文件测试的首选协议。Windows 可通过 UNC 路径（例如 `\\测试电脑\ReelNestTest`）或映射盘访问；macOS 通过 Finder 连接 SMB 服务器后访问挂载目录；Linux 在系统完成文件系统挂载后选择对应目录。路径仅为示例，不表示已经建立共享。桌面文件管理器显示的网络位置也不一定是 Dart 文件 API 可访问的本地路径，必须以实际可列目录、可读文件为准。

原版 `SourcesView.swift` 的 `connectAndPickDirectory()` 接受 `smb://`、`ftp://`、`ftps://`，调用 `NSWorkspace.shared.open(url)` 交给系统处理，再用 `NSOpenPanel` 从 `/Volumes` 选择目录，最后调用 `addNetworkMountedSource`。接受协议字符串不等于原版内置了对应协议客户端，也不保证每个系统都能挂载它们。

当前 ReelNest 使用 `DirectoryAccess` 和 `FileSourceAdapter` 访问系统已经提供的目录，尚未迁移原版网络设备连接、凭据协调及重新挂载流程，没有自建 SMB/NFS 客户端。原版网络设备入口仍在迁移范围中，不能把“先由系统挂载”当成最终删除该入口的理由。NAS 不需要安装 ReelNest Server 才能作为目录来源。

协议与系统能力参考：[Microsoft SMB 文件共享说明](https://learn.microsoft.com/en-us/windows-server/storage/file-server/file-server-smb-overview)、[Apple 连接共享电脑与服务器](https://support.apple.com/en-hk/guide/mac-help/mchlp1140/mac)。

## 分层验证

| 层次 | 无 NAS 时的环境 | 检查内容 | 不能据此宣称完成的项目 |
|---|---|---|---|
| 规则与状态 | 注入路径探测结果、内存数据库 | 路径边界、分类、忽略状态、取消和过期结果 | 真实网络、系统授权、文件解码 |
| 文件与索引集成 | 独立临时目录、合成文件、NFO、本地图片、独立 SQLite | 扫描、父子关联、重扫、缺失/恢复、持久化 | 实际播放、NAS 拔插 |
| 应用冒烟与播放 | 可解码的测试视频/音频、图片、字幕及 NFO | 原生目录选择、浏览、详情；播放器接入后的播放、拖动进度、续播 | 不同厂商 NAS、不同系统挂载行为 |
| SMB 集成 | Windows 共享专用测试目录，由另一台电脑连接 | 列目录、读取、权限变化、连接断开/恢复和扫描取消 | 所有 NAS 型号兼容性 |
| 平台验收 | Windows/macOS/Linux 原生运行 | 授权持久化、挂载识别、窗口/UI、网络与播放行为 | 未运行的平台或设备 |

当前 63 项测试及静态分析已通过，见 [测试记录](TEST_REPORT_2026-10-08.zh-CN.md)。它们包含前两层的部分覆盖，不代表此表全部完成。现有部分 `.mkv` 测试文件仅包含合成文本，用于验证文件名与索引，不能用于播放验收；组件测试中的平台切换也不能代替对应系统原生运行。

## 媒体样本准备

后续应用冒烟使用项目自行生成的色条/图形视频与测试音频，无需用户提供电影收藏。样本包含电影、两季剧集、特别篇、中文及空格文件名、NFO、可解码海报、外置字幕，以及缺少元数据的条目。字幕、播放和续播的验收等对应功能接入后执行。

样本必须遵守原扫描规则：普通视频来源当前最低为 50 MiB，音乐新来源为 512 KiB。短小视频可能被正确过滤，不能为让样本显示而修改产品默认值。用于普通电影/剧集冒烟的可播放样本应生成到超过视频阈值，并记录实际文件大小和解码结果；阈值测试则单独保留边界样本。大文件在本地生成，不提交进 Git。

临时集成测试继续使用独立目录与数据库。手工冒烟样本使用专用目录和清单，不混入用户目录；删除、移动、断开连接等故障操作只针对该测试目录。没有生成的资源、没有执行的步骤均保持待验证状态。

## 不购买 NAS 的网络验证

Windows 本身可以作为 SMB 文件服务器，因此可将专用样本目录设为共享，让现有 Mac 通过 SMB 访问。先用系统工具确认能列目录、读取文件，再验证 ReelNest。macOS 端应用测试需要先补齐当前缺失的目录持久授权；尚未补齐时只能确认系统共享链路。

同机访问共享可以检查 UNC/SMB 路径，但无法充分模拟真实网络中断与延迟。后续优先使用两台设备的局域网连接；Linux 端仍需自己的原生环境。共享配置、凭据与防火墙调整在执行网络测试时单独处理，本次只记录方案，没有开启共享或安装服务。

重点故障场景：扫描前断开、扫描中断开、恢复后重扫、无权限、根目录在线但单个文件消失，以及挂载点卸载后仍留下可读空目录。最后一种是当前已知缺口：缺少挂载身份检测时，空目录可能被当作成功空扫描并清理旧索引，必须修复并验证后才能宣称挂载盘保护完整。
