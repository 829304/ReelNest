## 关闭保存失败与 Linux 卷身份修复

用户要求先确认问题，再修复。先读取 C 盘当前实现，随后增加两项回归，在修改业务代码前执行：关闭保存失败后解码器应保留、块设备缺少 UUID 应视为未知。两项均失败：前者实际 engine 为 null，后者仍返回仅包含挂载路径/ext4/设备名的身份，证明问题存在。

### 修复

- `PlaybackSession.close` 改为先取消周期检查、暂停并等待保存；失败时不释放引擎、不永久关闭会话，恢复周期检查并解除关闭门禁。保存成功后释放，用户明确放弃保存时才使用 `discardProgress`。重复关闭请求共享进行中的任务；关闭成功后保持幂等。
- 关闭弹窗重试再次失败时保留窗口和会话；成功后释放并关闭。“仍然关闭”明确跳过新保存再释放；弹窗取消/消失不会隐含放弃进度。`finally` 解除页面关闭门禁。
- Linux 挂载表定位到当前最深挂载，再用 `lsblk` 的显式 JSON 列读取文件系统 UUID。设备编号或虚拟文件系统的块设备来源只用于查找，持久身份使用 UUID。UUID 缺失/冲突、查询错误及查询期间挂载/UUID 改变时返回未知；嵌套未知挂载不退回父盘身份。网络文件系统保留服务器/共享路径身份，不查询块设备。
- 外部探测同时读取 stdout/stderr，各限 1 MiB，等待限 5 秒，防止管道堵塞或无限等待。没有修改 Windows/macOS 身份算法、引入历史数据库兼容或自动重建来源。
