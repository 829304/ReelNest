## 分三批实施

| 批次 | 交付 | 验收条件 |
|---|---|---|
| E1：连接与选库 | 协议客户端、来源独立会话、安全凭据、连接/选库入口、保存和重启恢复、重新认证 | 可登录取库；错误密码、超时、限制接入有明确提示；取消不误保存；本地来源回归通过 |
| E2：同步与浏览 | 库范围、分页、电影/系列/季集映射、海报与基本详情、索引和同步状态 | 无重复遗漏、来源隔离；失败/取消保留旧索引，完整成功后才处理删除；可浏览电影/剧集 |
| E3：播放与进度同步 | 远程资源准备、mpv 网络播放、续播/队列、开始/进度/停止上报、原远程痕迹同步模式 | 可播放、跳转、切集；关闭正确上报；本地和服务端记录按原模式协调；认证失效不无限重试 |

先实现 E1，形成可单独检查的交付，再推进 E2/E3。“能登录”不代表完整支持 Emby；不继续把高级播放器项加入本批前置范围。

## 代码边界

沿用 [项目结构](PROJECT_STRUCTURE.zh-CN.md)，暂不拆仓库或独立包。

- `apps/client/lib/api/emby/`：HTTP、鉴权、DTO、响应与错误，不依赖 Widget/SQL。
- `apps/client/lib/sources/emby/`：选库范围、条目映射、同步与播放资源，不把远程同步伪装成本地目录扫描。
- `features/sources/`：原版连接/选库 UI、会话协调、保存/重新认证和同步任务。
- 公共浏览/详情：接入第二种真实来源时按需要提取本地浏览逻辑；旧 Mlink 试验契约不是公共接口。
- `features/playback/`：区分文件和远程资源准备，复用已有 mpv 会话/队列/记录；播放器不负责登录或拼 URL。
- `platform/`、`storage/`：安全存储保存凭据，SQLite 保存来源配置与索引；只维护当前初始结构，不增加开发版本升级链，不自动删除开发数据库。

客户端身份使用 ReelNest 品牌与稳定设备标识。来源/账号/会话隔离，密码和令牌不进入普通配置或日志；鉴权资源在使用前准备和刷新。

## 测试与完成条件

1. 本机模拟 HTTP 服务验证真实协议请求：地址与代理路径、鉴权、选库、分页、缺字段、401/403/限制接入、超时、中途失败及取消。
2. 临时 SQLite 与安全存储替身验证持久化、来源/账号隔离、改选库、索引保留和观看同步模式；按原版区分空选择、空库和异常响应。
3. 本地 HTTP 提供自生成媒体，验证真实 mpv 网络播放/跳转/切集和上报。这些替身不能代替真实 Emby 兼容验收。
4. 全量回归、静态分析、Windows 原生与 Release 构建/启动；macOS/Linux 在对应环境验证，不把 Windows 结果当作三端通过。
5. 最终用真实 Emby 验证登录、库范围、海报/详情、播放、续播/已看与重新认证。现在无需用户先提供服务器，先实现模拟服务回归，真实服务条件到验收时再确认。
