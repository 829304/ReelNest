# 2026-10-11 媒体库滚动开销优化

本批解决媒体库滚动时发现的重复工作，不调整卡片布局、菜单功能或浏览规则。原 MediaLib 只读参考，未清理用户数据库、凭据或缓存，未提交推送。

## 原因与修改

- 卡片右键菜单原先在每次构建时遍历完整快照，分别查找当前条目、子集和父系列。进入视口的每张卡片都会重复执行。快照现在一次建立来源隔离的身份与父子索引；大库索引随快照在后台 isolate 建立，菜单按键查找，保留系列播放记录、已看状态及右键操作规则。快照列表不可变，同一目的地的浏览范围可以安全复用；新快照会建立新的索引和范围。
- 页面缓存同一快照、同一目的地的题材与排序可选项，不再因搜索输入、同步进度或选择状态变化反复聚合全库。
- 海报原先无论显示大小都请求 512×768 的解码目标；现在按实际宽度乘设备像素比例，向上取 64 像素尺寸档，显示与两行预热共用尺寸键。150 px、1 倍缩放示例变为 192×288，目标像素量减少约 86%；2 倍缩放为 320×480。解码仍保持源图比例、不放大原图，布局与裁切不变。仅调整内存解码，服务器取图和磁盘缓存键沿用原规则。
- 图片缓存校验原先额外解码一份 700×1050 图像再丢弃，现在完整解析首帧但只生成 1×1 校验图；保留损坏图片拒绝、重新下载、大小上限和失败退避。实际显示由图片管线按需解码。
- 卡片悬停/焦点变化复用海报组件实例，避免重复构建图片子树；切换条目或来源仍会更新图片，布局依赖与图片 Provider 刷新继续生效。

参考原版：`Views/PosterGridView.swift` 的惰性网格、两行预热；`Views/AppColors.swift` 的解码许可、尺寸档和缓存规则。
