# ReelNest 文档维护规范

- 状态：Active
- 负责人：项目文档维护者
- 最后更新：2026-10-13
- 适用范围：ReelNest 仓库全部 Markdown 文档
- 权威范围：文档分类、状态、验证措辞、更新与归档规则

## 目标

ReelNest 文档用于回答四个问题：原版应当怎样、当前代码做到哪里、还缺什么、有什么证据可以证明。文档数量不是目标；同一事实应有明确的权威来源，阶段记录不得覆盖产品边界，测试通过不得自动解释为功能或 UI 完成。

## 信息权威顺序

出现冲突时按以下顺序处理：

1. 用户最新明确指令和仓库根目录 `AGENTS.md`。
2. [项目边界与一致性要求](PROJECT_SCOPE.zh-CN.md)。
3. 原 MediaLib 指定源码基线及其依赖、测试。
4. ReelNest 当前代码、自动化测试和最新专项验证记录。
5. 实施计划、历史试验和早期阶段记录。

发现冲突时不能默默选择其中一份。应修正非权威文档，或明确标注其历史状态及适用时间。

用户明确批准的范围调整属于产品边界例外。此类决定必须同时写入 `AGENTS.md`、项目边界和独立决策记录；模块文档应明确区分“暂未迁移”和“已从当前产品范围移除”。历史实施记录保留当时事实，但应在入口处说明当前决定，不能继续把已移除能力列为后续缺口。

## 文档类型

| 类型 | 回答的问题 | 典型文档 |
|---|---|---|
| 项目约束 | 为什么做、做什么、不做什么 | `PROJECT_SCOPE.zh-CN.md` |
| 当前阶段 | 现在做什么、完成条件是什么 | `NEXT_STAGE.zh-CN.md` |
| 模块规格 | 用户行为、规则、状态与依赖 | 首页、播放器、连接器主文档 |
| 架构设计 | 模块如何协作、为什么这样设计 | `PROJECT_STRUCTURE.zh-CN.md` |
| 数据说明 | 数据身份、表结构、保留与删除 | `DATA_DICTIONARY.zh-CN.md` |
| UI 规范 | 页面结构、视觉参数和交互状态 | 模块规格及一致性清单 |
| 开发指南 | 如何搭建、运行、检查和构建 | `DEVELOPMENT.zh-CN.md` |
| 测试计划 | 需要验证什么、在哪个平台验证 | `MEDIA_TESTING.zh-CN.md` 等 |
| 验证记录 | 某次实际执行了什么、结果如何 | `TEST_REPORT_*`、专项修复记录 |
| 技术决策 | 为什么选择某个长期方案 | `decisions/` |
| 历史资料 | 已结束或撤销的方案和试验 | Mlink、系列摘要试验 |

模块的长期有效规则应写回模块主文档；日期型修复记录保存当时证据，不应成为查找当前规则的唯一入口。

## 文档状态

新建或大幅整理的文档使用以下状态之一：

| 状态 | 含义 |
|---|---|
| `Draft` | 尚在讨论，不能作为实现或验收依据 |
| `Active` | 当前有效并持续维护 |
| `Superseded` | 已被另一份文档替代，必须给出替代链接 |
| `Historical` | 只记录当时事实，不描述当前状态 |
| `Archived` | 不再维护，仅保留追溯 |

现有旧文档可渐进补充状态，不要求一次性机械修改全部文件。修改某份旧文档的实质内容时，应同时判断是否需要添加状态和替代关系。

## 推荐文档头

长期维护文档使用以下字段；不适用的字段可省略，但不能用虚假值占位。

```md
状态：Active
负责人：模块或文档负责人
最后更新：YYYY-MM-DD
适用范围：功能、平台或版本
权威范围：本文件负责定义的内容
原版基线：MediaLib 提交及源码入口
验证状态：已验证平台和待验证平台
```

阶段验证报告改用“验证日期、对应提交、环境、命令、结果、未覆盖范围”，不需要伪装成长期规格。

## 完成与验证等级

文档引用验证结论时应说明等级。低等级不能替代高等级。

| 等级 | 可以证明 | 不能证明 |
|---|---|---|
| V0 代码已接入 | 存在实现入口 | 可编译、可运行或符合原版 |
| V1 格式/静态分析通过 | 基础代码质量检查通过 | 业务正确 |
| V2 Dart 单元/组件测试通过 | 隔离规则或组件行为通过 | 原生插件和真实服务器正常 |
| V3 Release 构建通过 | 当前平台可生成产物 | 产物能启动或业务可用 |
| V4 启动冒烟通过 | 窗口创建、响应并正常退出 | 具体功能可用 |
| V5 原生业务场景通过 | 对应平台真实插件/窗口流程通过 | 其他平台或真实服务器通过 |
| V6 真实来源/服务器通过 | 指定真实环境的闭环通过 | 所有环境和视觉一致 |
| V7 原版功能/UI 对照通过 | 固定条件下完成一致性验收 | 未列入样本的所有设备均无差异 |

使用“已完成”时必须指出完成的是哪个范围。例如“Windows V5 播放场景通过”不能写成“播放器三端完成”。平台变体组件测试仍属于 V2。

## 事实、计划与历史的写法

- 当前事实使用“已接入”“已验证”，并附实现或验证链接。
- 尚未实现使用“待迁移”“计划”，不要使用会被理解为已经存在的现在时。
- 代码存在但没有运行验证时写“已静态接入，待验证”。
- 无法确认时写“待核对”，不要根据页面、字段名或旧计划推断完成状态。
- 历史段落使用明确日期，并说明不覆盖当前状态。
- 测试数量必须带日期、批次或对应提交；入口文档只保留最新记录。
- 构建成功、启动成功、真实服务器和 UI 对照分别记录，不能合并成笼统的“验收通过”。

## 品牌与术语

- 客户端名称为 **ReelNest**；中文品牌可使用“映栖”。
- 自有服务端及来源入口为 **ReelNest Server**。
- MediaLib / MediaLIB Server 只用于原源码、兼容协议和历史记录。
- 第一阶段平台写作“Windows、macOS、Linux 三个桌面端”，不简称“五端”。
- “媒体源”指用户配置的来源；`sourceId + localId` 共同构成媒体身份。
- Mlink 是历史协议/试验语境，不作为正常应用总架构名称。

界面文案应优先沿用原版和项目实际中文文案；内部类型名只用于开发文档。

## 命名与链接

- 长期文档使用稳定名称，例如 `DATA_DICTIONARY.zh-CN.md`。
- 批次或缺陷记录可使用 `TOPIC_YYYY-MM-DD.zh-CN.md`。
- ADR 使用 `decisions/NNNN-short-name.md`。
- 相对链接从当前文档位置解析；重命名文件时同步更新所有引用。
- 链接文字应说明目标内容，不使用连续多个“这里”。
- 本地绝对路径只用于记录实际产物或环境，不能作为跨设备操作说明的唯一入口。
- 日期采用 `YYYY-MM-DD`；用户可见时间使用 Asia/Hong_Kong（UTC+8）。

## 模块文档最低内容

新模块或重大补齐使用[模块规格模板](templates/MODULE_SPEC_TEMPLATE.zh-CN.md)，至少包括：

1. 目标与非目标。
2. 原版源码、依赖和测试依据。
3. 用户入口与完整流程。
4. 默认值、业务规则和页面状态。
5. 数据身份、持久化和写回边界。
6. 加载、失败、取消、重试和并发规则。
7. UI 参数、交互和平台差异。
8. 安全、隐私和性能边界。
9. 实现文件映射。
10. 验收矩阵、未完成项和已批准差异。

## 更新触发条件

| 变化 | 必须同步的文档 |
|---|---|
| 用户调整产品范围或优先级 | `AGENTS.md`、项目边界、当前阶段、文档索引；范围例外另建或更新决策记录 |
| 新增或完成模块 | 模块规格、当前阶段、文档索引、一致性清单 |
| 修改默认值或业务规则 | 模块规格、原版依据、相关测试说明 |
| 修改数据库结构或身份规则 | 数据字典、结构设计、相关模块规格 |
| 修改连接器协议 | 连接器主文档、数据/凭据边界、契约测试说明 |
| 新增平台实现或平台限制 | 平台验收矩阵、开发指南、模块规格 |
| 完成一轮验证 | 对应验证记录；入口文档只在成为最新状态时更新 |
| 修复长期规则缺陷 | 修复记录和模块主文档；不能只留下日期日志 |
| 放弃或替代方案 | ADR 或历史文档标为 `Superseded` / `Historical` |

## 归档规则

- 历史记录保留事实，不为了让旧数字看起来“最新”而改写原结论。
- 当日期型记录过多时，可按月份移动到 `history/YYYY-MM/`；移动前先把长期有效规则合并回模块主文档，并更新链接。
- 已撤销的试验必须在开头标明历史状态和替代方案。
- 不删除仍被决策、测试或源码映射引用的历史证据。
- 不把构建日志、测试日志、用户数据库、凭据或媒体样本提交为普通文档附件。

## 交付前检查清单

- [ ] 文档范围和状态明确。
- [ ] 当前事实有代码、原版源码或验证记录支撑。
- [ ] 计划、已实现、已验证和已验收没有混写。
- [ ] Windows、macOS、Linux 的结论分别记录。
- [ ] 自动化、原生、真实服务器和视觉验收分别记录。
- [ ] 未完成项和非目标没有被静默删除。
- [ ] 用户批准的范围例外已与普通“待迁移”能力分开，历史记录不会被误读为当前计划。
- [ ] 品牌、术语、默认值和路径符合项目约束。
- [ ] 新增文档已加入 `docs/README.md`。
- [ ] 相对链接可解析，标题和表格可正常渲染。
- [ ] 没有凭据、服务器地址、用户路径或其他不必要的敏感数据。
- [ ] 与当前代码同时变更时，文档对应同一提交或明确说明版本差异。

本规范用于约束后续文档写法，不追溯性地把所有旧记录改写成同一格式。历史文档的原始证据价值优先保留。
