## 已实现的流程

首页“管理媒体源” → 添加媒体源三步向导（来源选择 → 连接/目录与分类 → 设置/参与策略）→ 添加并扫描 → 浏览顶层媒体 → 电影详情或系列季集列表。来源行可打开设置、修改分类与参与策略并保存；来源主页 `SourceRow` 的 P0 实现已接入，但仍待原版逐像素/逐交互对照。系列/NFO/浏览和设置已接入；自动化、原生和三端验收状态以[平台验收矩阵](PLATFORM_VERIFICATION_MATRIX.zh-CN.md)为准。

文件来源使用同一个文件适配器，不需要 MediaLib 服务端、Mlink 登录或账号。一次多选目录，按目录名自动命名，跳过已有目录，新增目录按选择顺序扫描。每个来源使用随机生成的稳定 ID，文件主键为来源 ID 加目录内相对路径；系列用来源内系列目录（根目录散集则用剧名）编码生成独立键。重新定位根目录时保留来源 ID；相对路径不变的文件和系列保留身份。

默认产品路由已移除 Mlink 入口，首页不再初始化服务器会话。旧 Mlink 代码仅保留为历史试验；只有回归测试通过 `createRouter(enableLegacyMlink: true)` 才建立旧路由，正常应用不开放该开关。

## 扫描与文件保护

- 新增目录按原版默认递归扫描并忽略点号开头的文件/目录；Windows 同时检查系统 Hidden 属性，在进入隐藏目录前跳过。原生属性按最多 128 项分批在后台 isolate 读取；读取失败中止本轮扫描并保留旧索引，不作为成功空扫描。关闭 `ignoreHidden` 时不做隐藏检查。相应配置已存储，本地来源设置弹窗没有这两个编辑控件；macOS 非点号的原生隐藏标记仍待平台适配验证。
- 按原支持列表与来源分类处理视频、音频、图片；普通来源的图片是附属资源，不当媒体索引。扩展名入库不代表该文件可播放。
- 内部符号链接不跟随，防止循环和意外跨目录；用户所选根目录先解析为规范路径。相同根路径重复添加会拒绝，Windows 根路径查重忽略大小写；不去重相互嵌套的不同来源。
- 先枚举支持的文件清单，再逐文件提交正式索引。连接内临时表只记录本轮已导入身份，用于完整成功后的旧条目清理；不再整批暂存后发布。
- 一个剧集文件的系列和单集在同一事务中写入，扫描进度仍按文件计数；本轮保留集合同时记录父子身份。完整成功后的清理同时处理消失的单集和无剩余单集的系列；来源移除一并删除父子索引，不删除磁盘媒体。
- 单个文件读取或写入索引失败时继续其余文件并汇总错误。取消、部分失败和根目录不可访问时，保留原有索引及本轮已成功导入文件，成功扫描时间不变。取消是协作式的，已交给操作系统的文件 I/O 仍可能等待系统返回。
- 对照原版后改为：完整成功扫描删除未发现的旧索引，不删除媒体文件。离线、失败、取消时不清理旧索引。新增和重新定位时记录来源挂载信息，扫描开始及发布成功前重新比对；即使卸载后目录仍可读，也不以空扫描清理旧索引。未知信息或挂载变化会保留索引，需要恢复原挂载或重新定位确认；真实 NAS/移动盘拔插尚未验收。
- 重新定位需要确认新目录；移除来源需要明确确认，只删除该来源的应用索引，不触碰源文件。
- 应用入口使用单个本地扫描队列；重复来源请求去重，排队来源在开始前重查目录可达性，离线/失败后继续后续来源，支持取消活动或排队请求。仓储层同一来源也不允许重叠扫描。跨进程扫描锁与实时数据库刷新尚未实现。

## 自动监控与增量更新（2026-10-27，Windows 自动化/Release 验证通过）

全局“自动扫描间隔”默认关闭，选项为关闭、每 15 分钟、每小时、每 6 小时、每天；关闭时不启动文件监控或周期任务。开启后同时启用文件事件监控与周期完整扫描。来源设置中的 `autoScan` 可逐来源关闭；本地目录、移动硬盘和已挂载 NAS 路径均可参与，Emby/Jellyfin/Plex 等远程服务器来源不自动同步。扫描执行前再次检查该来源的 `autoScan` 状态。

文件事件按 1.2 秒合并。Windows/macOS 递归监控来源根目录；Linux 建立逐目录 inotify 监控树并在目录结构变化后重建。事件归属按最长根路径匹配。普通文件变化走 `scanChanges`；根路径变化、目录结构变化或原生事件溢出/中断走受保护的完整扫描。活跃扫描期间到达的变更进入后续队列；待执行变更按来源合并路径，完整扫描请求覆盖该来源的局部变更。周期扫描用于兜底并定期恢复监控。

增量扫描复用完整扫描的文件解析、NFO/海报读取及隐藏文件过滤。仓储只移除已确认缺失的媒体和空父系列；失败、取消或磁盘身份变化不删除旧索引，也不推进 `lastScan`。关闭全局自动扫描、移除来源、关闭来源 `autoScan` 时释放相应监听；应用退出先停止监控再关闭数据库。Native watcher 错误带 error/stack 交给 scanner 错误回调并脱敏写入 diagnostics，同时触发保护性完整扫描；单个来源的监听失败不阻塞其他来源。

最终验证：8 个文件 78/78 通过（16 秒，`apps/client/build/automatic-scan-tests.log`）：`automatic_source_scanner_test` 8 项，其余七文件沿用此前数量；包含真实文件通知到 `SourceScans` 再到数据库新增/重命名/删除链路及 watcher 错误回退。`flutter analyze` clean（4.6 秒，`automatic-scan-analyze.log`）；Windows Release 成功（43.4 秒，`automatic-scan-release.log`）；五秒 hidden smoke 于 `2026-10-27T20:54:10.8061317+08:00` 通过，窗口响应、正常关闭、ExitCode 0（`automatic-scan-smoke.json`）。这些最终日志已覆盖前一轮结果；来源 schema 未变。

平台边界：未运行全量测试、native Flutter drive、可见截图验收或真实 NAS/移动盘拔插。Windows 原生递归监控用例通过；另有一个在 Windows 强制 `perDirectory` 策略的测试，只验证该策略逻辑，不能作为 Linux 原生验收。macOS/Linux 仍待设备实机；macOS 持久目录授权缺口仍单独存在。NAS 文件事件可靠性受挂载方式和操作系统影响，依靠周期扫描兜底。

## 失效索引清理与挂载保护（2026-10-08）

仪表盘沿原版 `LibraryHealthCenterView` / `AppState.removeMissingItemsFromIndex` 接通单项“移出索引”和批量“清理失效索引”。确认弹窗明确只删除 ReelNest 内部索引，不修改媒体文件。忽略告警、来源离线或参与检查策略不会授权额外删除。

确认之后重新读取来源及索引，核对来源位置、设置和条目内容；健康候选重新计算，且通过逐层目录列举确认文件确实不存在。权限或 I/O 异常、恢复的文件、嵌套排除来源及状态不明的来源保留。提交前复查参与的挂载与数据库内容；应用内清理期间拦截扫描、来源修改/删除/重新定位。一次清理使用同一事务，失败整批回滚；删除最后一个失效单集时同时移除其无剩余子项的系列父项，保留其他来源和其余单集。

平台探测集中在 `platform/directory_safety.dart`：Windows 在后台查询卷 GUID/序列号/文件系统类型，网络盘查询 UNC 来源；Linux 读取 `/proc/self/mountinfo`，按最长路径边界选择挂载，再通过 util-linux 的 `lsblk` 读取本地文件系统 UUID；macOS 读取系统挂载表。网络挂载来源在保存前去除用户信息。平台查询失败视为未知；初次记录未知时禁止发布扫描，可重新定位确认。`access_identity` 只加入当前初始表，没有开发中间数据库迁移、重建或自动删除数据。

边界：Linux 本地卷身份包含文件系统 UUID，设备名与设备编号只用于查找卷，不作为持久身份；缺失 UUID、探测失败或查询过程中挂载/UUID 变化均视为未知，保留索引。网络挂载仍按文件系统、服务器与共享路径识别，不执行块设备查询。macOS 当前仍使用挂载点、文件系统类型和挂载来源，尚未接入卷 UUID，其替换磁盘边界仍待原生适配验收。应用内操作门禁不覆盖其他进程，SQLite 提交也不能与外部文件系统变更构成原子事务。原生网络 I/O 取消仍受系统返回时间约束。macOS 持久目录授权尚未完成，不因挂载表解析实现而开放其目录按钮。

## Linux 卷身份修复（2026-10-09）

已复现旧计算方法缺少卷 UUID 的问题。现改为挂载表定位 + `lsblk --json --list --paths --output NAME,MAJ:MIN,UUID` 的当前卷查询，UUID 查询前后比对挂载及身份，未缓存为长期结果；扫描和清理沿用已有的提交前复查。查询双管道并发读取，单管道上限 1 MiB、进程等待上限 5 秒。UUID 为空、不可读、候选冲突或挂载发生变化时返回未知，不退回设备名称身份，也不退回父挂载。

Linux 需要 util-linux 的 lsblk，常规 Ubuntu 桌面环境通常提供；缺失时安全保留索引。已有开发来源的旧 Linux 身份不会自动转换，确认正确目录后可通过现有“重新定位”重新登记，不自动清库或重建来源。Windows 和 macOS 身份算法未修改。本轮在 Windows 验证注入的 Linux 挂载/UUID 数据及真实临时目录/SQLite；Linux 原生命令和实盘替换仍待对应环境验证。

依据：[Linux 挂载表定义](https://www.kernel.org/doc/html/latest/filesystems/proc.html)、[lsblk 手册](https://man7.org/linux/man-pages/man8/lsblk.8.html)。
