# 本地媒体源与索引

日期：2026-10-05。第一轮架构纠偏实现：目录来源、扫描、持久化与浏览。播放器、完整元数据与第三方服务器直连尚未实现。

最新要求见[项目边界](PROJECT_SCOPE.zh-CN.md)：第一阶段三桌面端，功能与 UI 完全对照原版。本文仅记录当前代码，不是产品规范；简化页面、扫描默认值变化、缺失能力和 Mlink 入口移除均需审核纠正，不能视为用户同意的功能修改。

## 已实现的流程

首页“管理媒体源” → 添加媒体源 → 系统目录多选（本机、移动硬盘或已挂载 NAS）→ 指定分类 → 添加并扫描 → 浏览顶层媒体 → 电影详情或系列季集列表。来源行还可打开设置、修改分类并保存。当前添加弹窗仍不是完整三步向导。最新系列/NFO/浏览和设置保存已写入代码，按用户要求暂缓运行验收。

文件来源使用同一个文件适配器，不需要 MediaLib 服务端、Mlink 登录或账号。一次多选目录，按目录名自动命名，跳过已有目录，新增目录按选择顺序扫描。每个来源使用随机生成的稳定 ID，文件主键为来源 ID 加目录内相对路径；系列用来源内系列目录（根目录散集则用剧名）编码生成独立键。重新定位根目录时保留来源 ID；相对路径不变的文件和系列保留身份。

默认产品路由已移除 Mlink 入口，首页不再初始化服务器会话。旧 Mlink 代码仅保留为历史试验；只有回归测试通过 `createRouter(enableLegacyMlink: true)` 才建立旧路由，正常应用不开放该开关。

数据库位于平台应用支持目录的 `library/reelnest.sqlite`。源文件只读；此数据库不打开或修改旧 MediaLib 的数据库。保存来源配置、文件/系列索引与本地描述信息，尚未建立播放历史表。

参考旧 `MediaSource.swift`、`SourceRepository.swift`、`MediaScanner.swift`、`SourcesView.swift`，未宣称完整迁移旧扫描器。文件名解析已接入：自动来源区分电影、剧集与音乐，电影标题/年份、剧集季号/集号及系列目录写入索引；指定电影分类不会识别为剧集，其余分类按原 `resolvedMovieType` 处理未识别为剧集的视频。相册保留原文件名，图片归为照片、视频归为其他视频；音乐使用原曲目前缀清理规则，音频标签尚未读取。来源分类选择已接入：默认自动来源接受视频/音频；视频阈值 50 MiB，音乐新源默认 512 KiB，扫描音频取来源阈值与 512 KiB 的较小值；相册接受图片/视频且无大小下限。保险库分类待解锁/隐藏规则完成后开放。

系列父条目及单集关联已接入，父条目按原 `resolvedSeriesType` 分类；来源内顶层浏览只展示电影/系列等顶层条目，进入系列后按季查询。多季默认折叠、单季平铺，季号 0 为特别篇，空季号排最后。本地海报直接读取文件，扫描成功时间参与图片缓存键；旧服务端认证和图片接口不参与该链路。

NFO 按原 `LocalMetadataService` 的候选次序处理：单文件依次选择同名 NFO、`movie.nfo`、`tvshow.nfo`；系列目录先 `tvshow.nfo` 再 `movie.nfo`。只读第一个存在的候选，不跨文件合并字段；读取失败或无有效字段时由扫描器回退。读取标题、原名、正数年份及简介（plot 优先于 overview），保留原正则标签语义，不扩展为通用 XML 导入。海报按 poster/cover/folder，背景图按 fanart/backdrop/background，扩展名按 jpg/jpeg/png/webp/heic 的原顺序查找。两项来源策略分别控制文本读取与图片发现。

同一条目的重扫按原仓储保留本轮未读到的年份、简介、原名和图片等已存字段；影片/剧集/相册视频等身份类别切换时重置这些描述字段，避免旧值串入新类别。季集关系与季集编号按本轮扫描更新。当前仍未接入手工订正历史、音频标签、照片完整元数据、截图回退及在线刮削。背景图路径已保存，完整艺术照/背景展示链路另行迁移；HEIC 等图片的三平台解码还待验收。

上述字段只加入当前初始数据库结构，不提供开发中间数据库的升级逻辑，也不自动清理用户本机数据。

## 来源设置（2026-10-08，待运行验收）

本地设置按原 `SourceSettingsSheet` 只显示分类和参与策略，未增加名称、递归、大小阈值或 NFO 控件。保存使用独立草稿，取消不写入；相册/其他视频不参与元数据拉取，关闭元数据参与时也关闭写回。音乐保存沿用原严格大于 5 MiB 时调整为 512 KiB 的规则。元数据拉取、健康检查及写回服务尚未接入，策略值回显但不可操作，保险库仍需先完成保护规则。

存储由 `SourceRepository.updateSettings` 负责；`SourceScans.saveSettings` 协调“先保存，成功后再取消/重启”，只在这个流程中允许扫描期间更新配置。保存成功后全局仍有活动扫描，才结束旧任务并优先重扫编辑来源；原批次剩余请求取消，后追加的请求保留，重复请求共享完成信号。空闲保存不自动扫描；保存失败不取消原任务。通过仓储变更流刷新来源与详情，既有媒体分类在下一次扫描才重新识别。健康缓存和原通知服务仍未迁移，页面暂复用现有提示方式。

本批只通过格式化与静态分析，尚未执行运行验收。没有新增数据库升级或自动删除开发数据。

## 本地健康检测（2026-10-08，后续批次）

`features/health` 已接入本地来源离线、文件缺失与影视元数据缺口，以及仪表盘对应列表。“参与健康检查”现可编辑；元数据拉取/写回依旧未接执行服务。设置变更、来源移除/重定位和扫描结束会取消旧检测、清空旧结果并重算。探测异步执行，不在数据库事务或 Widget 构建里访问文件系统；每轮复用相同路径的探测结果，界面消费已派生的快照。

来源离线和可清理候选分离；忽略告警不会让离线条目变成可清理条目。检测不改写媒体索引，不删除文件。元数据完整性沿原规则检查影视顶层条目的封面/年份/简介，音乐标签缺口待标签模型迁移；相册与其他视频不计入影视缺口，照片文件本身仍可被缺失检测报告。

忽略/恢复状态保存在当前初始表 `ignored_health_issues`，以类别、来源 ID 和本地身份隔离；重开应用可读取。没有新增升级或自动清理开发数据库。索引清理、在线补充、音乐/重复项/链接等检测和完整仪表盘 UI 尚未完成。本批只做静态分析，以上实际行为仍待测试。

## 扫描与文件保护

- 新增目录按原版默认递归扫描并忽略点号开头的文件/目录；Windows 同时检查系统 Hidden 属性，在进入隐藏目录前跳过。原生属性按最多 128 项分批在后台 isolate 读取；读取失败中止本轮扫描并保留旧索引，不作为成功空扫描。关闭 `ignoreHidden` 时不做隐藏检查。相应配置已存储，本地来源设置弹窗没有这两个编辑控件；macOS 非点号的原生隐藏标记仍待平台适配验证。
- 按原支持列表与来源分类处理视频、音频、图片；普通来源的图片是附属资源，不当媒体索引。扩展名入库不代表该文件可播放。
- 内部符号链接不跟随，防止循环和意外跨目录；用户所选根目录先解析为规范路径。相同根路径重复添加会拒绝，Windows 根路径查重忽略大小写；不去重相互嵌套的不同来源。
- 先枚举支持的文件清单，再逐文件提交正式索引。连接内临时表只记录本轮已导入身份，用于完整成功后的旧条目清理；不再整批暂存后发布。
- 一个剧集文件的系列和单集在同一事务中写入，扫描进度仍按文件计数；本轮保留集合同时记录父子身份。完整成功后的清理同时处理消失的单集和无剩余单集的系列；来源移除一并删除父子索引，不删除磁盘媒体。
- 单个文件读取或写入索引失败时继续其余文件并汇总错误。取消、部分失败和根目录不可访问时，保留原有索引及本轮已成功导入文件，成功扫描时间不变。取消是协作式的，已交给操作系统的文件 I/O 仍可能等待系统返回。
- 对照原版后改为：完整成功扫描删除未发现的旧索引，不删除媒体文件。离线、失败、取消时不清理旧索引。若卸载后仍暴露可读空目录，当前缺乏挂载身份检测，可能被视为成功空扫描；NAS/移动盘拔插尚未验收。
- 重新定位需要确认新目录；移除来源需要明确确认，只删除该来源的应用索引，不触碰源文件。
- 应用入口使用单个本地扫描队列；重复来源请求去重，排队来源在开始前重查目录可达性，离线/失败后继续后续来源，支持取消活动或排队请求。仓储层同一来源也不允许重叠扫描。跨进程扫描锁与实时数据库刷新尚未实现。

## 平台状态

当前目录入口对 Windows、Linux 开放；本轮仅在 Windows 实际构建/验证。移动硬盘与已挂载 NAS 是路径接入方式，不包含挂载协议、网络发现或独立 SMB/NFS 客户端。

macOS 的沙盒持久授权/bookmark、Android SAF 持久授权、iOS 文件导入/授权尚未接入，三者目录按钮明确禁用并说明原因，不把普通路径保存冒充权限持久化。参考 [file_selector 的平台能力](https://pub.dev/packages/file_selector)。Windows/Linux 保存路径，重启后依靠当前用户的系统权限访问；失去权限时需恢复访问或重新定位。

Drift 的原生连接使用后台 isolate 执行 SQL，依据 [Native Drift 文档](https://drift.simonbinder.eu/platforms/vm/)。开发阶段只维护当前初始表结构，包含分类、阈值、来源策略及必填的创建/更新时间。`schemaVersion = 1` 是 Drift 所需的初始标识，没有历史升级分支或开发版本兼容承诺；实际发布后有需要再设计升级。已有开发数据库不会被程序自动删除或重建。大库扫描和网络盘性能尚未专项测量。
