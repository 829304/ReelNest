# 本地媒体源与索引

日期：2026-10-05。第一轮架构纠偏实现：目录来源、扫描、持久化与浏览。播放器、完整元数据与第三方服务器直连尚未实现。

最新要求见[项目边界](PROJECT_SCOPE.zh-CN.md)：第一阶段三桌面端，功能与 UI 完全对照原版。本文仅记录当前代码，不是产品规范；简化页面、扫描默认值变化、缺失能力和 Mlink 入口移除均需审核纠正，不能视为用户同意的功能修改。

## 已实现的流程

首页“管理媒体源” → 添加媒体源 → 选择本地文件夹、移动硬盘或已挂载 NAS → 系统目录选择器 → 添加并扫描 → 浏览媒体 → 查看文件信息。

三类文件来源使用同一个文件适配器，不需要 MediaLib 服务端、Mlink 登录或账号。可以保存多个来源，每个来源使用随机生成的稳定 ID，媒体主键为来源 ID 加目录内相对路径。重新定位根目录时保留来源 ID；相对路径不变的文件保留媒体身份。

默认产品路由已移除 Mlink 入口，首页不再初始化服务器会话。旧 Mlink 代码仅保留为历史试验；只有回归测试通过 `createRouter(enableLegacyMlink: true)` 才建立旧路由，正常应用不开放该开关。

|---|---|
| `domain/media_source.dart` | 六种来源类型、来源内媒体身份、索引条目、取消信号 |
| `sources/source_adapter.dart` | 来源采集边界，目前由文件适配器实现 |

| `features/sources/data/source_repository.dart` | 来源保存/定位/移除、扫描发布、分页查询与来源隔离 |
| `features/sources/application/source_providers.dart` | 依赖装配、数据刷新与逐来源扫描进度 |
| `features/sources/presentation/` | 来源管理、添加目录、索引浏览与文件信息 |

数据库位于平台应用支持目录的 `library/reelnest.sqlite`。源文件只读；此数据库不打开或修改旧 MediaLib 的数据库。只有来源配置与文件索引，尚未建立播放历史表。

参考旧 `MediaSource.swift`、`SourceRepository.swift`、`MediaScanner.swift`、`SourcesView.swift`，未宣称完整迁移旧扫描器。视频目前仍临时归为其他视频，元数据解析待迁移。2026-10-05 的对照批次已恢复原扫描过滤：默认自动来源接受视频/音频；视频阈值 50 MiB，音频取来源阈值与 512 KiB 的较小值；相册接受图片/视频且无大小下限。分类已存入模型，当前简化添加表单仍默认自动分类。

## 扫描与文件保护

- 可选择是否扫描子目录、是否忽略点号开头的文件/目录；不等同于 Windows 的 Hidden 属性过滤。
- 按原支持列表与来源分类处理视频、音频、图片；普通来源的图片是附属资源，不当媒体索引。扩展名入库不代表该文件可播放。
- 内部符号链接不跟随，防止循环和意外跨目录；用户所选根目录先解析为规范路径。相同根路径重复添加会拒绝，Windows 根路径查重忽略大小写；不去重相互嵌套的不同来源。
- 每 100 条写入 SQLite 临时暂存表，只有遍历完整成功且没有收到取消才通过事务更新正式索引。暂存表属于当前数据库连接，关闭/崩溃后不会残留为已发布内容。
- 取消、部分读取失败和根目录不可访问时，保留上次索引和成功扫描时间。取消是协作式的，已交给操作系统的文件 I/O 仍可能等待系统返回。
- 对照原版后改为：完整成功扫描删除未发现的旧索引，不删除媒体文件。离线、失败、取消时不清理旧索引。若卸载后仍暴露可读空目录，当前缺乏挂载身份检测，可能被视为成功空扫描；NAS/移动盘拔插尚未验收。
- 重新定位需要确认新目录；移除来源需要明确确认，只删除该来源的应用索引，不触碰源文件。
- 应用入口使用单个本地扫描队列；重复来源请求去重，排队来源在开始前重查目录可达性，离线/失败后继续后续来源，支持取消活动或排队请求。仓储层同一来源也不允许重叠扫描。跨进程扫描锁与实时数据库刷新尚未实现。

## 平台状态

当前目录入口对 Windows、Linux 开放；本轮仅在 Windows 实际构建/验证。移动硬盘与已挂载 NAS 是路径接入方式，不包含挂载协议、网络发现或独立 SMB/NFS 客户端。

macOS 的沙盒持久授权/bookmark、Android SAF 持久授权、iOS 文件导入/授权尚未接入，三者目录按钮明确禁用并说明原因，不把普通路径保存冒充权限持久化。参考 [file_selector 的平台能力](https://pub.dev/packages/file_selector)。Windows/Linux 保存路径，重启后依靠当前用户的系统权限访问；失去权限时需恢复访问或重新定位。

Drift 的原生连接使用后台 isolate 执行 SQL，依据 [Native Drift 文档](https://drift.simonbinder.eu/platforms/vm/)。数据库版本独立于旧应用，当前 schema 2；从 schema 1 补充分类和文件大小阈值，保留原记录，不自动扫描。大库扫描和网络盘性能尚未专项测量。
