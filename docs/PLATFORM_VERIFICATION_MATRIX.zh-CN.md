## 使用方式

本表汇总“已实现到哪里”和“在哪个平台实际验证过”，不替代各模块的详细规格和测试报告。状态符号：

- ✅：在该平台完成表中注明的原生验证等级。
- ◐：已有实现或部分证据，但尚未完成该平台闭环。
- 🧪：只有 Dart/组件平台变体或模拟环境验证，不是原生验收。
- ⬜：未实现或没有可引用的验证记录。
- ⚠：存在明确限制或仍需专项复验。

验证等级 V0–V7 见[文档维护规范](DOCUMENTATION_GUIDE.zh-CN.md#完成与验证等级)。同一行的三个平台必须分别记录；Windows 结果不能推导 macOS/Linux 已通过。

照片/相册、照片查看器、系统照片库、照片搜索和首页照片墙已按用户决定移出当前产品与三桌面端验收矩阵，不应以“未实现”计入平台缺口。三端仍需回归验证照片入口不可见、既有照片数据不被删除且不混入视频范围；影视海报、背景、演员图片及其缓存继续按视频能力验收。证据见[照片范围记录](PHOTO_SCOPE_DECISION.zh-CN.md)。

## 跨平台自动化的解释

组件测试中设置 `TargetPlatform.windows`、`macOS` 或 `linux`，可以检查条件分支、文案、主题和部分布局，验证等级仍为 V2。它不能覆盖：

- 原生插件注册和生命周期。
- 文件选择器、目录权限、挂载和安全存储。
- 多窗口消息、系统焦点、输入法和辅助功能。
- media_kit/libmpv 的实际解码与资源释放。
- 系统字体、材质、缩放和 GPU 渲染。
- 安装、签名、公证和系统升级。

CI 中声明某个平台构建也不能自动视为该平台已验证；只有存在可引用的成功工作流或本机记录时才能更新为 V3。

## 当前必须保留的验收缺口

### Windows

- 使用真实 Emby 完成登录恢复、浏览、搜索、播放、字幕、进度与状态写回。
- 测量真实大库的首屏和滚动帧率，而不是只引用合成索引耗时。
- 复验最新代码下的播放器关窗、主窗口交互和数据库关闭日志。
- 与原 macOS MediaLib 按固定数据完成 UI/交互对照。

### macOS

- 实现并验证持久目录授权。
- 完成 Release 构建、启动、目录扫描、播放、多窗口、防休眠与安全存储原生验证。
- 使用原版同机或等效固定条件完成视觉和交互对照。
- 完成签名、公证和应用权限设计后再进入发布验收。

### Linux

- 完成 Release 构建与目标发行环境启动。
- 验证目录选择、UUID 挂载身份、断开恢复、libsecret 和 libmpv。
- 验证窗口、输入、缩放、桌面环境差异和运行时依赖打包。
- 明确支持的发行环境后再形成安装与发布结论。

## 更新规则

每次平台验证后更新对应单元格，并链接到包含以下信息的证据：

1. 日期、ReelNest 提交和操作系统版本。
2. 实际执行命令或人工步骤。
3. 使用模拟服务还是真实服务器。
4. 是否读写用户数据或服务器状态。
5. 通过、失败、跳过和已知诊断。
6. 未覆盖范围。

没有证据链接时不得将 🧪 或 ◐ 改为 ✅。修复某个缺陷也不能顺带提升同模块的其他平台或其他验证等级。
