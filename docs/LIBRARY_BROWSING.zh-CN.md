# 媒体浏览与详情

更新：2026-10-04。状态：已完成 Windows 构建及部分自动化冒烟；真实服务、视觉对照和边界场景仍待验证。已执行范围见[验证记录](WINDOWS_SMOKE.zh-CN.md)。

## 当前流程

分类页 → 对应类型分页列表 → 媒体详情。列表支持海报/文字列表切换、最近更新/标题/年份排序、下拉刷新、手动刷新、加载更多、空结果及错误重试。详情展示接口实际提供的海报、原名、年份、简介、题材、评分、时长和音视频信息。返回列表保留当前路由中的排序、视图和滚动控制器。

2026-10-05 范围纠正：本文记录已有 Mlink 试验路径，不是完整重构架构。后续保留可复用的浏览/详情组件，将数据和状态从单个 Mlink 会话解耦，改由文件来源与 Emby/Jellyfin/Plex 适配器提供；旧 MediaLib 服务端扩展不再是前置依赖。当前仍没有播放、收藏编辑或离线媒体缓存。界面参数与差异见[源码映射](design/SOURCE_MAPPING.md)，新排期见[实施计划](FLUTTER_IMPLEMENTATION_PLAN.zh-CN.md)。

## 已核对的接口

| 接口 | 本轮使用 |
|---|---|
| GET `/api/v1/library/browse` | `type`、`offset`、`limit=48`、`sort`，排序值为 recentlyUpdated/title/year |
| GET `/api/v1/items/{id}` | 普通条目和系列容器的资料；单集可能附带 episodeContext |
| GET `/api/v1/series/{id}` | 本地服务端新增系列摘要路由；仅在发现信息含 series-detail 时使用 |
| GET `/api/v1/series/{id}/episodes` | 只使用返回上下文中的季；season 为非负季号或 unspecified，并带 offset/limit |
| GET `/api/v1/images/{id}/poster?size=320` | 受鉴权保护的海报缩略图 |

所有请求使用 Bearer 请求头。查询由 Uri 编码，路径 ID 按单个组件编码，并拒绝斜杠、反斜杠、控制字符、`.` 和 `..`。API 响应被映射成纯 Dart 模型，不接受服务端提供的任意图片 URL 或本机媒体路径。

每页验证 offset/limit 回显、整数总数、hasMore、页大小和页内重复 ID；跨页按 ID 去重，而下一页 offset 使用服务端原始页长度推进。若还有下一页但整页为空，或加载更多时没有新增 ID，停止并提示重试/刷新，避免循环请求。分页上限沿用服务端 offset 1,000,000。服务端在分页期间发生变动可能造成 offset 分页遗漏，用户可刷新重新读取；它不是快照分页。

## 系列与评分的实际边界

参考基线已有 `ServerSeriesDetail` 和 `seriesDetail` 数据提供器，但当时 `ServerDiscoveryHTTPHandler` 只公开 `/api/v1/series/{id}/episodes`。本轮在旧 MediaLib 的独立本地分支 `codex/series-summary-api` 补上只读 `GET /api/v1/series/{id}`，复用现有数据提供器及其逐用户授权；发现信息增加 `series-detail` 能力。尚未编译、部署或联调，不能据此认为远程服务器已支持。

打开系列详情（包括手动刷新）时重新读取发现信息，并核对服务器 ID。只有能力包含 `series-detail` 才调用新路由；旧版服务仍通过 `/api/v1/items/{id}` 显示基本资料及升级提示。新路由的 404、权限错误或无效响应直接显示错误，不降级隐藏问题。服务器升级后无需重新登录，刷新系列详情即可重新协商。

客户端将系列摘要与单集上下文分开建模，共用季列表解析与页面。系列默认选择服务端返回的第一个季分组；单集优先选择自身所在季，当前单集高亮且不重复跳转自身。支持第 0 季（特别篇）、正常季号和 `unspecified`（未分季），显示总集数、分季观看统计，按季分页进入单集详情。仅使用服务端返回的季，不猜测季号或抓取 HTML。完整契约与部署顺序见[系列摘要接口](SERIES_API.zh-CN.md)。

`ServerLibraryItem` 没有社区评分字段。卡片只展示标题、进度、已看状态以及悬停时的类型/年份；详情在 communityRating 存在时显示 10 分制评分。userPreference.rating 是当前用户的 5 分制评分，不能混用。不会为每张卡额外请求详情以填评分。

## 页面与数据生命周期

- 分页控制器以会话代次、分类、排序、系列和季组成键。刷新从 offset 0 开始；旧请求即使后返回也不覆盖新请求。
- 首次失败显示重试；追加失败保留列表和原 offset，重试同一页；刷新失败保留旧结果并提示。图片错误不使整页失败。
- 普通业务网络请求允许并发；会话恢复、保存、刷新和清除仍串行。并发 401 比较原请求 token，复用已经轮换的令牌，而不是每张图片各刷新一次。每个读请求只在 401 后重试一次；Riverpod 的详情和图片自动重试已关闭。
- 登录成功、退出与会话失效会改变代次。发送前、响应返回后和刷新前后都核对代次；过期结果不能进入新账号。会话失效通过仓库通知同步到连接页面，各业务页转为登录提示。
- 退出先清空内存状态并使旧代次失效，再排队清除存储，图片队列不会阻挡本机状态退出。已经发送的网络请求可能继续结束，但结果会被丢弃。

## 海报加载

图片经 Mlink 网络层取得 Uint8List，使用内存 ImageProvider 显示。令牌不进入 URL、路由参数、缓存键或日志。请求不跟随重定向，不依赖 Cookie；允许 JPEG/PNG/WebP/GIF 响应，限制单张编码数据 4 MiB；JSON 仍限 1 MiB，每次请求总超时 10 秒。

图片仓库按会话隔离，同时最多 4 个网络请求，同 ID 合并在途请求。编码字节缓存最多 64 项且不超过 16 MiB，按最近使用淘汰。解码目标宽度 320；控件更换图片或销毁时移除对应 Flutter 图片缓存项。图片不再被页面使用时取消尚未发送的排队任务；已发送任务允许结束，但仍检查会话代次。会话页面解绑后图片仓库销毁，待处理队列失败结束，不写磁盘缓存。

无海报用占位图标；请求或解码失败可手动重试。分页海报墙按需构建格子，详情海报沿用相同鉴权管道。缓存上限指编码字节，不是整个应用内存上限；滚动性能和解码内存需后续实测。
