# 媒体库进入详情的海报闪烁修复

日期：2026-10-12。范围：Emby 视频海报；不改变页面布局与操作流程。

## 原因与修复

1. 详情元数据返回后，页面将详情获取时间作为海报版本。它通常晚于媒体库扫描时间，使同一海报的网络、磁盘和解码缓存身份改变。普通进入详情现在沿用媒体库海报版本；明确执行详情刷新时仍使用新的版本。
2. 卡片与详情海报显示尺寸不同，解码缓存按尺寸区分。即使已有海报字节，较大尺寸仍需异步解码，原实现会短暂显示占位图。现在解码期间显示同一来源、作品、图片类型、版本的已有缓存图，完成后替换为目标尺寸。

缓存预览只维护有界的键索引，复用现有 ImageCache，不额外持有像素副本；内存压力与释放时清理索引。不同服务器和图片版本不会相互借用预览。

参考原仓库 AppColors.swift 的 ArtworkImageCache，以及 PosterGridView.swift 同步使用 cachedImage 的行为。原仓库保持只读。

## 验证

- 详情元数据时间晚于扫描时间时，进入详情仍使用扫描版本。
- 人为延迟详情尺寸的图片加载，切页期间仍有实际海报像素，不出现占位图。
- 缓存预览不跨来源、版本或图片类型；内存压力后预览索引清空。
- 相关测试 28 项通过；完整测试复跑 435 项通过；flutter analyze 无问题；git diff --check 通过。
- Windows Release 构建成功，标准 Release 目录已更新。隐藏窗口启动与响应检查通过，正常关闭退出码为 0；stderr 只有渲染后端信息。
- 首轮完整测试中 Emby 同步向导测试在模拟服务器关闭阶段出现连接中断；单独复查 21 项以及完整复跑均通过，未修改该测试来绕过失败。

本次验证不代表真实服务器端的首次下载耗时已消除；没有可复用缓存时仍需要下载与解码。Windows 原生启动检查也不替代用户实际媒体库的视觉验收。
