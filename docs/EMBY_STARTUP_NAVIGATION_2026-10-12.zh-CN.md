# Emby 启动侧栏修复（2026-10-12）

## 原因与实现

启动时已保存的媒体库目录由 `embyBrowseCatalogProvider` 读取，但侧栏没有使用它生成入口，仍订阅并等待完整 `EmbyVideoSnapshot`。完整快照会读取所有媒体、单集、观看记录、偏好和详情，再建立索引；大库启动时因此先出现空入口和折叠数量 0。来源列表本身还进行了全库数量统计，展开操作也要等待偏好写入后才更新界面。

- 侧栏改用不统计媒体数量的来源配置查询，以及独立的库目录 provider。已有目录直接从本机 SQLite 读取；首次尚无目录时沿用原有服务器 Views 请求。
- “全部视频／想看／收藏”可见性改为限定来源和顶层条目的轻量探测；最多每批读取 64 条必要分类字段，找到可见条目即停止。不读取单集、完整详情、播放记录或完整视频快照。
- 查询显式使用已有 `media_parent` 索引，想看探测先检查偏好，再连接远程元数据，避免排序导致 SQLite 改扫完整来源。
- 保留原版库目录排序、选择范围、音乐目录排除、分类规则和折叠数量含义（入口数量，并非影片数量）。加载尚未完成时不显示临时 0；目录可先显示和点击，不等待想看／收藏探测。
- 展开／收起立即更新界面，保存串行执行，快速点击以最后一次操作为准；保存失败提示并恢复最近成功保存的状态。来源刷新期间保留已有导航；同步后刷新保存的目录。

原版参考：`MediaLib/Sources/MediaLib/Views/ContentView.swift` 的 `embySourceGroup` 与 `embyExpansionBinding`。本次调整内部读取顺序，不添加新功能、不更改数据库结构、不清理用户数据。
