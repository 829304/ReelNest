# 基础播放设置与防休眠

2026-10-09：最初按用户要求只做静态实现；后续用户授权测试，现已通过全量 167 项单元/组件测试（含本批新增 11 项）及 Windows 3 项原生业务场景，静态分析与格式检查通过。构建/启动记录见 [当日测试报告](TEST_REPORT_2026-10-09.zh-CN.md)。macOS/Linux 原生与完整 UI 验收仍待进行。

## 原版依据与入口

- `PlayerView.swift`：`PlayerInlineSpeedControl`、`PlayerSettingsPopover`、`PlayerAdvancedSettingsOverlay` 的播放行为组及设置行尺寸。
- `AppSettings.swift`、`MpvPlayerController.swift`、`TrackPreferenceStore.swift`：默认值、续播和本片/系列倍速偏好。
- `SettingsView.swift`：主设置页的“已看判定”，没有将阈值搬到播放器高级设置。
- `PlayerControllerSupport.swift`：播放时同时阻止显示器和系统自动休眠，暂停与关闭时释放。

播放器快捷设置提供当前倍速；“打开内置播放器设置”提供基础播放行为行。主设置页接入已看阈值。只迁移这一批可用设置，不添加尚未实现的片头片尾等占位控件；完整设置和 UI 对照仍未完成。

## 已写入的规则

| 项目 | 默认与行为 |
|---|---|
| 当前倍速 | 0.5–3x，拖动即时应用，松手记忆；提供原版吸附档位 |
| 默认倍速 | 默认 1x，可选 0.75/1/1.25/1.5/2；在下次打开视频时应用，不直接覆盖当前倍速 |
| 本片倍速记忆 | 默认开启，按来源加系列/影片身份保存；选回 1x 清除偏好，下次使用默认倍速；关闭开关不删除旧偏好 |
| 变调保护 | 默认开启，交给 mpv 的 `audio-pitch-correction`；修改时应用到当前播放器 |
| 快进/快退 | 默认 5 秒，可选 5/10/15/30 秒，左右键采用设置值 |
| 记忆进度 | 默认开启；关闭后下次从头播放，仍保存观看记录 |
| 恢复回退 | 默认 5 秒，可选关闭/5/10/15/30 秒；记录超过 10 秒才回退，结果不低于零 |
| 自动标记已看 | 默认开启；关闭后继续存进度，不新增自动已看标记，不清除已有已看 |
| 已看判定 | 主设置页选择 70/80/90/95%，默认 90%；保存进度时重新读取阈值，使独立播放器窗口使用最新选择 |
| 启动音量 | 默认不开启，沿用上次视频音量；开启后使用设定的 0–100%，默认 80% |

设置存入已有 `player_preferences` 表；基础行为使用一个 JSON 设置项，主设置页的已看阈值使用独立设置项，避免不同窗口互相覆盖。没有新增数据库版本、迁移分支或第三方依赖。会话内修改按顺序执行并基于最新会话状态更新；变调设置保存失败时尝试恢复原设置，错误保留在设置界面。

## 三桌面端防休眠

同一 Flutter 引擎聚合正在播放的解码器，原生窗口各自持有请求。切片期间释放旧解码器不应释放新视频的请求。暂停、播完、播放出错与关闭释放，原生对象销毁也清理请求。

- Windows：独立 Power Request，分别请求显示器与系统保持唤醒。
- macOS：沿用原版 `ProcessInfo.beginActivity` 的两个禁止空闲休眠选项。
- Linux：GTK 的 idle/suspend inhibition，实际效果需在目标桌面会话验证。

`Video(wakelock: false)` 保留，避免底层仅显示器唤醒与本轮原生服务重复管理。请求失败通过可恢复的提示报告，不当作解码失败。主窗口与独立播放器窗口均注册通道。
