# 数据库读取与关闭优化

本轮在前端性能检查基础上审查数据库事务、快照读取和增量写入。原版只读参考 `LibraryReloadCoordinator.swift`：完整读取保持数据库快照一致性，阻塞工作在后台执行。

## 修改

- **快照查询合并**：原先先读取全量媒体并等待后台 JSON 解码，再在同一事务中查询同一批媒体的观看状态、偏好和详情；事务结束后又启动一次后台计算。现在一次联表查询取得媒体、远程元数据、活动时间、偏好、进度及详情。事务内只做数据库读取，事务结束后统一解码和构建搜索词/快照。来源、视图与条目仍在同一事务读取，保留标题排序和一致性。
- **增量收藏查询收窄**：禁用远程轨迹同步时，`RemoteIndexWriter` 原先读出该来源全部远程 JSON，再在 Dart 提取收藏状态。现在仅按本批条目 ID 查询，由 SQLite 提取布尔收藏字段；避免少量新增条目触发全库元数据解码。收藏保留规则不变。
- **事务结束后再关闭**：`LibraryDatabase` 记录已经进入的根事务，关闭时等待提交/回滚，拒绝新的根事务；已开始事务的嵌套事务仍可结束。数据库和 SourceRepository 关闭均幂等。事务内部请求关闭会立即报错，避免等待自身。原来的主窗关闭后 provider dispose 重复关闭也不会重复执行底层关闭。

## 验证

- 全量测试 **429 项通过**，静态分析无问题。
- 使用真实后台 SQLite 连接，确定性阻塞事务后发起关闭：验证关闭等待、提交持久化、回滚不持久化、嵌套 savepoint、拒绝新事务、重复关闭和避免自等待。
- 临时数据库中的无关条目故意设置坏 JSON，验证增量写入不读取它且仍保留目标条目的本地收藏。三万条快照、观看状态、手动评分、筛选等既有回归继续通过。
- Profile `lib/main.dart` 构建及 2026-10-11 20:22（UTC+8）原生启动/退出烟测通过，退出码 0，该次日志没有出现数据库关闭异常。
- Release 编译完成，但标准目录的安装阶段因正在运行的旧程序占用而失败。根据本次 CMake 安装脚本将完整 Release 产物安装到 `apps/client/build/windows/x64/runner/DatabaseAuditRelease`，不结束用户程序。该目录 20:24 原生启动/退出烟测通过，退出码 0，stderr 同样没有数据库关闭异常。标准 Release 目录未完成本轮更新；应使用独立目录中的 `reelnest.exe`，并保留整个目录。

没有将本轮描述为整页固定倍数提速。快照仍是全量读取，测试总耗时会受并行用例和机器负载影响；本轮主要减少查询/后台传输次数，并把 CPU 工作移出数据库事务。此前观察到的关闭错误本次未复现，但一次原生检查不代表所有关闭竞态已排除。

## 后续优先级

状态变化触发全库快照重建仍是较大开销，后续应区分来源结构与单条观看状态更新。需要同时验证跨窗口通知、筛选和排序一致性。现有同步写入已按 250 条批处理，本轮保持其原子性和取消回滚，不把完整同步拆成会暴露半成品的提交。

未更改数据库 schema、添加迁移、删除用户数据或修改原仓库。
