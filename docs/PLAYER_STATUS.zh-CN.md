# 本地视频播放器实现盘点

盘点日期：2026-10-09。本文为当前状态总表，历史批次文档中的旧“待做”段落不能作为最新状态。盘点依据原版 `PlayerView.swift`、`MpvPlayerController.swift`、`AppSettings.swift` 与 ReelNest 的 `features/playback`、`player` 实际代码；上述三个原文件在参考基线 `64f8ee2` 与原仓库当前 HEAD 之间没有变化。

## 结论与范围

基础本地视频播放、续播、音轨/本地字幕和剧集连播已接通，并运行了 Windows 原生测试；完整原版播放器尚未迁移完毕，UI 也没有完成一比一验收。

此前按基础播放、字幕/音轨、队列三个小批次推进，没有先提供完整剩余清单；部分旧文档仍把已完成的队列列为待办，造成进度不透明。下表统一状态。剩余项来自原版，不是新产品功能；今后拆分批次不应增加范围，确需调整时单独说明。

这里盘点的是本地**视频**播放器。音乐播放器、照片查看、媒体库扫描/元数据、NAS 连接/挂载、服务器连接器不是同一个模块。它们仍在整个项目范围内，但不能混入本地视频播放器完成率。服务器鉴权/播放地址、远程上报、画质/转码和离线缓存应在对应资源与连接器批次推进。

## 基础设置验证（Windows）

2026-10-09 用户授权测试后，当前/默认倍速、本片或系列倍速记忆、变调保护、步长、续播记忆与回退、自动已看与主设置阈值、启动音量通过专项回归。Windows 防休眠通道可创建/释放系统与显示器请求；聚合释放规则通过测试，实际空闲超时仍待人工检查。macOS/Linux 原生防休眠已写代码，尚未在对应平台编译或运行。

全量 167 项单元/组件测试（新增 11 项）、Windows 3 项原生业务场景、静态分析及 122 文件格式检查通过。详见 [基础播放设置](PLAYER_BASIC_SETTINGS.zh-CN.md) 和 [当日记录](TEST_REPORT_2026-10-09.zh-CN.md)。不代表完整播放器或一比一 UI 已完成。

## 验证现状与局限

- 最新全量 **167 项单元/组件测试**通过，这是整个客户端的测试总数，不是播放器功能完成率。
- Windows **3 项原生业务场景**通过：独立窗口解码/续播/切换/关闭，多音轨/字幕原生渲染和控制，真实 EOF 的三种结束行为与损坏下一集保护。
- 测试媒体为自己生成的 AVI/Matroska/SRT，尚未全面覆盖真实音频听感、设备插拔、多编码/HDR/长视频、真实 NAS/磁盘拔插。macOS/Linux 原生未验收。
- 原版与当前图标/字体/材质等没有完成逐项视觉验收，不能称一比一完成。未产生更新时间事件的开发索引条目，其顶层相邻排序仍有已记录的对照缺口。
- 当前 `Video` 仍设置 `wakelock: false`，本轮另写原生显示器/系统防休眠服务；Windows 通道创建/释放成功，实际空闲超时和 macOS/Linux 仍未验证。

## 建议的后续安排

建议把“本地基础播放闭环”与“完整原版播放器迁移”分别跟踪，避免把全部高级播放器选项都追加为接 Emby 的前置任务。基础设置与 Windows 本地流程回归已经完成，下一阶段优先推进 Emby；以上高级项继续保留在共用播放器迁移清单，不删除功能、不降低 UI 一致性标准。

基础设置已完成本轮 Windows 自动化验证，最新构建/启动结果见 [当日记录](TEST_REPORT_2026-10-09.zh-CN.md)；分批实现细节见 [基础播放](LOCAL_PLAYBACK.zh-CN.md)、[字幕音轨](PLAYER_TRACKS.zh-CN.md)、[队列](PLAYER_QUEUE.zh-CN.md)。
