# 演员作品批量读取与偏好增量刷新

日期：2026-10-21。承接性能审查中的两个待优化点；不改数据库结构、产品规则或用户配置。

## 演员作品

`cachedPersonWorks` 仍先使用同来源的有效会话缓存。未命中时，读取演员关联 ID，再分别批量读取作品和父剧集，使用现有 `indexedSelection` 的 JSON ID 参数及主键访问路径。保留关联行原有遍历顺序、父剧集去重、年份排序、媒体库范围和来源隔离；没有批量请求服务器或改变在线作品分页逻辑。

新增查询计数回归：1000 条剧集关联加电影、剧集父项、音乐项，整个本地回退只执行 4 次 SELECT（来源、关联 ID、作品、父项），不再逐作品/逐父项查询。无匹配或无父项时会少于 4 次。测试同时验证音乐排除、库范围、来源隔离及删除后的结果。

## 想看与评分

`SourceRepository` 维护内容版本和分来源的偏好版本。想看/评分事务成功后更新偏好版本并保留原有全局通知，失败不会发布偏好变更。其他内容变更仍更新内容版本。

Emby 展示快照分成内容基础快照与偏好覆盖层：偏好变更仅重查当前来源的 `media_library_preferences`，复用已解析的作品、播放记录、演员搜索词等；值未变化的条目对象直接复用。新快照重建分类缓存，确保想看筛选能立即增删条目。其他来源不因本次偏好变更重新加载。

播放器窗口通知以及显式错误重试改为失效基础快照，避免旧播放进度或读取错误被内容缓存保留。首页、详情、侧栏继续接收全局通知，不以屏蔽通知换取性能。

边界：这不是所有操作都做到单条 O(1) 更新。覆盖层仍读取当前来源的偏好表，并遍历快照、重建必要索引；不再重读和解析整库元数据/详情。首页等旧订阅者仍可能刷新自己的查询。没有添加常驻搜索 isolate。

## 回归证据

`apps/client/test/library_incremental_reads_test.dart` 检查实际 SQLite 读取次数、元数据对象复用、只查询一次偏好表、另一来源不重载、想看分类更新、评分清空、事务失败、内容变更、来源删除，以及首次内容读取期间发生偏好写入时不会丢失更新。已有播放器通知测试覆盖进度排序和剧集观看状态。

相关五个测试文件合计 80 项通过；最终全量测试 838 项通过、10 项按配置跳过，静态检查与 diff 检查通过。Windows Release 构建成功，5 秒隐藏窗口响应及正常退出检查通过，退出码 0，stderr 仅含渲染后端信息。日志为 apps/client 下 incremental-final-tests.log、incremental-all-tests.log、incremental-analyze.log、incremental-release-build.log。测试中的数据均为内存数据库，不删除本机媒体库。
