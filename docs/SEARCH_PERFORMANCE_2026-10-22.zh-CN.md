# 搜索性能优化：2026-10-22

## 首页搜索数据复用

HomeRepository 将一次查询的数据准备与搜索词匹配分开：读取媒体/详情后，构建包含 HomeVideo 和搜索字段的不可变文档；后续搜索词复用该文档，不重复读取整库或解析详情 JSON。原有中文、拼音、首字母、演员、子剧集字段及来源/隐私范围规则保持不变。

缓存键包含来源与 homeSearchScope，并验证 SQLite 当前连接的 total_changes() 和其他连接提交引起的 data_version。任何检测到的数据库写入都保守地使缓存失效，包括详情写入、删除和播放器连接写入；不是仅依赖 UI 通知。完成前再次校验来源范围和数据库版本，过期任务不能回填缓存或发布旧结果。

缓存最多 4 个来源，总计不超过 50,000 个顶层搜索文档、8×1024×1024 个搜索字段 UTF-16 码元，按最近使用淘汰。字符限制不等于整个对象图的内存字节上限。超限数据仍完整搜索，但不保留索引。缓存位于仓库实例内，不写数据库或用户配置，没有新增常驻线程。冷启动仍需读取和解析；查询之间发生写入时仍会重新构建。

## 取消 Emby 过期搜索

embyVideoResultsProvider 在释放/重建时取消其 ScanCancellation；大列表筛选改用已有 runHomeSearchWorker，可实际终止后台 isolate。异步读取边界检查取消，避免已过期查询继续启动后续工作。未修改 180 ms 输入防抖、过滤及排序规则。

这次未实现持久搜索 isolate；拼音静态缓存仍不能跨短生命周期 worker 复用。首页已存在的后台取消机制继续保留。

首页缓存命中后的后台匹配阈值沿用原始数据行数（超过 180 行），不按聚合后的顶层作品数判断。因此单部剧集包含大量分集时，匹配仍在后台执行。
